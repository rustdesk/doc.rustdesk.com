В этом руководстве описано, как установить RustDesk Server OSS, открыть нужные порты в брандмауэре и подключить клиенты к новому собственному серверу.

## Как лучше всего установить RustDesk Server OSS?

В большинстве случаев рекомендуется установка через Docker: её проще всего повторить, обновить и перенести на другой сервер. Если вы предпочитаете системные службы в Linux, хорошо подойдут и сценарий установки systemd или пакеты Debian.

## Какой способ установки выбрать?

| Способ | Кому подходит | Зачем его использовать |
| --- | --- | --- |
| Docker | Большинству собственных серверов | Самые простые обновления, предсказуемая настройка и лёгкий откат |
| Сценарий установки | Администраторам Linux, которым нужно быстро получить службы systemd | Устанавливает `hbbs`, `hbbr` и упрощает настройку клиентов с меньшим объёмом ручной работы |
| Пакет Debian | Системам на основе Debian, где используются пакетные инструменты | Установка ближе к штатному управлению пакетами |

## Требования к серверу
Требования к оборудованию очень низкие: достаточно минимальной конфигурации простого облачного сервера, нагрузка на процессор и память минимальна. Можно использовать и Raspberry Pi или что-то похожее. Что касается сети: если прямое соединение с пробивкой NAT через TCP не удалось, будет расходоваться трафик ретранслятора. Трафик соединения через ретранслятор — от 30 КБ/с до 3 МБ/с (экран 1920x1080) в зависимости от настроек разрешения и частоты обновления экрана. Для офисной работы это около 100 КБ/с.

## Брандмауэр {#ports}
Если у вас установлен UFW, настройте брандмауэр следующими командами:
```
ufw allow 21114:21119/tcp
ufw allow 21116/udp
sudo ufw enable
```

{{% notice warning %}}
Когда включён WebSocket (порты `21118`/`21119` открыты для [веб-клиента](https://rustdesk.com/web/)), `hbbs`/`hbbr` доверяют заголовкам `X-Real-IP` / `X-Forwarded-For` входящих WebSocket-соединений, чтобы определить настоящий IP-адрес клиента, — так IP-адрес клиента сохраняется, когда трафик WebSocket проходит через обратный прокси ([WSS](/docs/ru/self-host/rustdesk-server-pro/faq/#8-add-websocket-secure-wss-support-for-the-id-server-and-relay-server-to-enable-secure-communication-for-all-platforms)). Эти заголовки не проверяются, поэтому любой, кто может напрямую подключиться к `21118`/`21119`, может подделать заголовки и выдать себя за произвольный IP-адрес. Это позволяет обойти ограничения частоты запросов и блокировки по IP и подменить IP-адреса в журналах.

Если вы используете веб-клиент, открывайте порты WebSocket только через обратный прокси, который сам устанавливает `X-Real-IP`, и ограничьте доступ к `21118`/`21119` правилами брандмауэра так, чтобы к ним мог подключаться только обратный прокси. Если вы не используете веб-клиент, держите порты `21118` и `21119` закрытыми.
{{% /notice %}}

## Установка
### Способ 1: Docker (рекомендуется)

```
bash <(wget -qO- https://get.docker.com)
wget rustdesk.com/oss.yml -O compose.yml
sudo docker compose up -d
```

Подробнее см. [Docker](/docs/ru/self-host/rustdesk-server-oss/docker/).

### Способ 2: установка собственного сервера как службы systemd с помощью простого сценария
Сценарий размещён на [Techahold](https://github.com/techahold/rustdeskinstall), поддержка — в нашем [Discord](https://discord.com/invite/nDceKgxnkV).

Сейчас сценарий скачивает и настраивает ретранслятор и сигнальный сервер (hbbr и hbbs), создаёт конфигурации и размещает их на защищённой паролем веб-странице, чтобы их было легко раздать клиентам.

Выполните следующие команды:
```
wget https://raw.githubusercontent.com/techahold/rustdeskinstall/master/install.sh
chmod +x install.sh
./install.sh
```

В репозитории [Techahold](https://github.com/techahold/rustdeskinstall) есть также сценарий обновления.

Запишите IP-адрес или DNS-имя и ключ, которые будут показаны в конце установки, и введите их в клиенте в разделе «Настройки» > «Сеть» > «ID/Ретранслятор» в поля `Сервер ID` и `Ключ` соответственно, а остальные поля оставьте пустыми (см. примечание ниже).

### Способ 3: установка собственного сервера как службы systemd из deb-файла для дистрибутивов Debian

[Скачайте](https://github.com/rustdesk/rustdesk-server/releases/latest) deb-файлы и установите их командой `apt-get -f install <filename>.deb` или `dpkg -i <filename>.deb`.

## Что нужно клиентам после установки сервера?

Когда сервер запущен, клиентам обычно нужны адрес `Сервер ID` и открытый `Ключ` сервера. Для клиентов RustDesk Server Pro может понадобиться также `Сервер API`. См. [здесь](/docs/ru/self-host/client-configuration/#2-manual-config).
