Этот справочник поможет разобраться в расширенных настройках собственных клиентов RustDesk и в том, как каждая настройка ведёт себя на разных уровнях приоритета.

Здесь описаны все расширенные настройки собственных клиентов.

## Что такое расширенные настройки собственных клиентов RustDesk?

Расширенные настройки — это низкоуровневые параметры клиента, которыми можно управлять через собственные клиенты RustDesk, пользовательские настройки и политики на стороне сервера. Они полезны, когда нужно одинаковое поведение на множестве клиентов или более строгий контроль над безопасностью, разрешениями и настройками интерфейса по умолчанию.

## Как работает приоритет настроек?

| Источник | Приоритет |
| --- | --- |
| Переопределение (Override) | Наивысший |
| Стратегия (Strategy) | Высокий |
| Пользователь (User) | Средний |
| По умолчанию (Default) | Наименьший |

## Коротко о расширенных настройках

- Настройки переопределения имеют приоритет над всеми остальными источниками
- Настройки стратегии могут переопределять пользовательские настройки и настройки по умолчанию
- Пользовательские настройки действуют, только если их не переопределяет источник с более высоким приоритетом
- Настройки по умолчанию — запасной уровень
- На этой странице приведены точные ключи настроек, значения, значения по умолчанию и примеры

## Уровни приоритета настроек

Есть четыре типа настроек:

1. Настройки переопределения: `Web Console` → `Custom Clients`
2. Настройки по умолчанию: `Web Console` → `Custom Clients`
3. Пользовательские настройки — в клиенте RustDesk
4. Настройки стратегий: `Web Console` → `Strategies`

Иерархия приоритетов этих настроек: `Override > Strategy > User > Default` (переопределение > стратегия > пользователь > по умолчанию).

### whitelist

Использует белый список IP-адресов.

**Где находится**:

1. **Компьютер** Настройки → Безопасность → Безопасность → Использовать белый список IP
2. **Мобильные** Настройки → Демонстрация экрана → Использовать белый список IP

| Нужна установка | Значения | По умолчанию | Пример |
| :------: | :------: | :------: | :------: |
| N | `,` или `<ip1>,<ip2>,<ip3>` | `,` — без фильтра | `whitelist=,` |

Поддерживается нотация CIDR, например `whitelist=192.168.1.0/24,10.0.0.5`.

### id-whitelist

Использует белый список ID. Подключаться к этому устройству смогут только ID из списка.

Поддерживаются подстановочные знаки: `*` соответствует любому количеству символов, `?` — ровно одному символу. Регистр не учитывается.

**Примечание**: ID сообщает подключающийся клиент, поэтому это не механизм аутентификации. Белый список снижает риски, но не заменяет пароль или 2FA.

**Где находится**:

1. **Компьютер** Настройки → Безопасность → Безопасность → Использовать белый список ID
2. **Мобильные** Настройки → Демонстрация экрана → Использовать белый список ID

| Нужна установка | Значения | По умолчанию | Пример | Версия |
| :------: | :------: | :------: | :------: | :------: |
| N | `,` или `<id1>,<id2>,<id3>` | `,` — без фильтра | `id-whitelist=123456789,98765432?,abc*` | >= 1.5.0 |

### video-save-directory

Папка для сохранения записанных видео.

Для записей на управляемой стороне, которые делает установленная служба Windows, используйте [`windows-service-video-save-directory`](#windows-service-video-save-directory).

**Где находится**:

1. **Компьютер** Настройки → Общие → Запись → Папка для сохранения видео
2. **Мобильные** Настройки → Запись

Значения по умолчанию:

1. **macOS** ~/Movies/**app_name**
2. **Linux** ~/Videos/**app_name**
3. **Windows** %USERPROFILE%\Videos\\**app_name**
4. **Android** /Storage/emulated/0/**app_name**/ScreenRecord

**Примечание**: вместо **app_name** подставляется название текущего приложения.

### windows-service-video-save-directory

Папка, в которую установленный клиент Windows сохраняет записи, когда работает как служба. Путь должен быть абсолютным. Пустой или относительный путь игнорируется, и RustDesk использует папку по умолчанию.

| Нужна установка | Значения | По умолчанию | Пример |
| :------: | :------: | :------: | :------: |
| Y | Абсолютный путь Windows | `<system drive>\ProgramData\<app_name>\recording` | `windows-service-video-save-directory=D:\RustDesk\recordings` |

### relay-fallback-delay

Сколько секунд уже установленное соединение через ретранслятор ждёт прямого соединения WebRTC, прежде чем будет использован ретранслятор. Увеличьте значение, чтобы дать медленному прямому соединению больше времени; уменьшите, чтобы быстрее переходить на ретранслятор, когда прямое соединение установить не удаётся.

Действует, только когда включён WebRTC (`enable-webrtc`). В настольной версии это поле скрыто, если WebRTC выключен. Оставьте поле пустым, чтобы использовать значение по умолчанию — 2,5 секунды. Недопустимые, нулевые и отрицательные значения тоже заменяются значением по умолчанию.

**Где находится**:

**Компьютер** Настройки → Общие → Другое → Использовать подключение WebRTC P2P → Задержка перед переходом на ретранслятор в секундах

Доступно начиная с RustDesk 1.5.0

| Значения | По умолчанию | Пример |
| :------: | :------: | :------: |
| Положительное число секунд или пусто | 2.5 | `relay-fallback-delay=2.5` |

### floating-window-untouchable

По умолчанию нажатие на плавающее окно открывает меню. Если сделать окно «некликабельным» (untouchable), нажатия и свайпы будут проходить сквозь плавающее окно и передаваться окну под ним. После этого положение плавающего окна изменить нельзя, а система может автоматически сделать его полупрозрачным. В небольшом числе приложений, например в приложении GitHub, эта функция может не работать.
