В этом руководстве описано, как подключить RustDesk Server Pro к каталогу LDAP для централизованной аутентификации и поиска пользователей.

## Что даёт LDAP в RustDesk Server Pro?

LDAP позволяет RustDesk Server Pro проверять пользователей по вашей службе каталогов, а не вести отдельные локальные учётные данные для каждой учётной записи. При первом успешном входе RustDesk автоматически создаёт пользователя на основе его данных в LDAP.

## Порядок настройки LDAP

1. Определите хост LDAP, порт и режим шифрования (`389`, `636` или StartTLS).
2. Выберите служебную учётную запись с действующими Bind DN и паролем.
3. Укажите правильные Base DN, область поиска и фильтр пользователей.
4. Укажите правильный атрибут имени пользователя, например `uid` или `sAMAccountName`.
5. Проверьте настройку в веб-консоли RustDesk, прежде чем включать её для всех.

## Коротко о LDAP

- RustDesk создаёт пользователя при первом успешном входе через LDAP
- Консоль проверяет подключение к LDAP, когда вы сохраняете настройки
- Перевести локальных пользователей в пользователей LDAP пока нельзя
- Группы LDAP пока не поддерживаются

## Настройка
Откройте страницу настроек `LDAP`, как показано ниже.

![](/docs/en/self-host/rustdesk-server-pro/ldap/images/ldap.png)

- **LDAP Host:** имя хоста или IP-адрес сервера LDAP. Например, `ldap.example.com` или `192.0.2.1`.

- **LDAP Port:** номер порта, на котором работает сервер LDAP. Порт по умолчанию для LDAP — `389`, для LDAPS (LDAP через SSL) — `636`.

- **Base DN:** начальная точка поиска в LDAP. Например, dc=example,dc=com.

- **Scope:** область поиска в каталоге LDAP. Может быть one (только записи непосредственно под базовым DN) или sub (все записи ниже базового DN, включая вложенные).

- **Bind DN / Password:** имя и пароль служебной учётной записи администратора. С этой учётной записью выполняется подключение (bind) к LDAP для проверки других пользователей. Часто это DN пользователя вида `cn=admin,dc=example,dc=com`.

- **Filter:** фильтр поиска для запроса LDAP. Например, `(objectClass=person)` или `(&(age=28)(!(name=Bob)))`.

- **Username Attribute:** атрибут, в котором хранится имя пользователя. Например, `uid` или `sAMAccountName`. По умолчанию используются `uid` и `cn`. Вот [обсуждение](https://github.com/rustdesk/rustdesk-server-pro/issues/140#issuecomment-1916804393) этой темы.

- **StartTLS:** использовать ли StartTLS, чтобы перевести соединение в защищённый режим.

- **NoTLSVerify:** пропускать ли проверку TLS-сертификата. Рекомендуется оставить false (то есть проверять сертификат), если вы не уверены в том, что делаете.

## Как это работает?
- Как работает вход через LDAP: нужно ли сначала создавать пользователя или RustDesk создаёт его при первом входе?
  > RustDesk создаёт пользователя при первом входе
- Как проверить, что LDAP работает (в идеале — командой, которая выведет найденных пользователей)?
  > Когда вы сохраняете настройки, RustDesk подключается к серверу LDAP с указанными binddn и паролем и проверяет, что всё работает.
- Как перевести локальных пользователей в пользователей LDAP?
  > Пока нельзя
- Поддерживаются ли группы LDAP?
  > Пока нет
