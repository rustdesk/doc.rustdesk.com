Роли управления определяют, что пользователю разрешено делать во время удалённого сеанса в RustDesk Server Pro.

Роль управления позволяет настроить разрешения на удалённое управление для разных пользователей. Когда пользователь управляет другим устройством, роль управления определяет, какие действия ему разрешены после установления подключения.

## Когда использовать роль управления?

Используйте роль управления, когда нужно ограничить действия оператора после подключения к удалённому устройству. Например, если нужно решить, может ли оператор передавать файлы, пользоваться буфером обмена, открывать терминал, перезагружать удалённое устройство или менять его настройки.

## Коротко о ролях управления

- Роли управления влияют на действия во время сеанса, после установления подключения
- Они не решают, разрешено ли само подключение
- У каждого пользователя может быть только одна роль управления
- Разрешения роли управления могут переопределять локальные настройки разрешений на управляемом устройстве
- Встроенные роли `Not Logged` и `Default` действуют для пользователей без назначенной собственной роли

{{% notice note %}}
**Роль управления, контроль доступа и стратегия**

- **Роль управления**: определяет, какие действия разрешены управляющему пользователю после установления подключения.
- **Контроль доступа**: определяет, может ли подключение между управляющим и управляемым устройствами вообще быть установлено.
- **Стратегия**: меняет настройки на управляемом устройстве.
{{% /notice %}}

## Требования

- Управляемое устройство: RustDesk **1.4.5** или новее (управляемые устройства на Android пока не поддерживаются)
- Управляющее устройство: без требований к версии

### Режим конфиденциальности

Для разрешения **Privacy Mode** (режим конфиденциальности) нужны RustDesk Server Pro **1.8.7** или новее и RustDesk **1.4.7** или новее на управляемом устройстве. Более старые управляемые клиенты игнорируют это разрешение.

## Расчёт разрешений

### Как работают разрешения

Коротко: разрешения управления имеют приоритет над локальными настройками.

Есть два источника настроек разрешений:

- **Локальные настройки на управляемой стороне**: настройки управляемого устройства (Настройки → Безопасность → Разрешения)
- **Разрешения управления**: разрешения роли управления управляющего пользователя (настраиваются в веб-консоли)

У каждого разрешения три состояния:

- **Use Client Settings**: без переопределения, используется локальная настройка управляемого устройства
- **Enable**: разрешение явно включено (переопределяет локальную настройку)
- **Disable**: разрешение явно отключено (переопределяет локальную настройку)

Разрешения рассчитываются для каждого сеанса:

| Разрешение управления | Локальная настройка | Результат |
|---|---|---|
| Enable | Enable | Enable |
| Enable | Disable | **Enable** |
| Disable | Enable | **Disable** |
| Disable | Disable | Disable |
| Use Client Settings | Enable | Enable |
| Use Client Settings | Disable | Disable |

**Особый случай: изменение удалённой конфигурации**

Когда к одному устройству подключено несколько управляющих пользователей, разрешение «Remote Configuration Modification» (изменение удалённой конфигурации) рассчитывается по всем подключениям:

| Разрешения управления во всех подключениях | Результат |
|---|---|
| Хотя бы одно Disable | **Disable** |
| Нет Disable, хотя бы одно Enable | **Enable** |
| Везде Use Client Settings | Используется локальная настройка |

### Какая роль применяется

Каждому пользователю можно назначить только одну роль управления. Есть две встроенные роли:

| Роль | Описание |
|------|-------------|
| **Not Logged** | Для управляющих пользователей, которые не вошли в учётную запись. Нельзя назначить пользователям. |
| **Default** | Для вошедших управляющих пользователей без назначенной роли управления или с явно назначенной ролью Default. |

Применяемая роль управления зависит от того, вошёл ли управляющий пользователь в учётную запись, и от назначенной ему роли:

| Состояние управляющего пользователя | Назначенная роль | Какая роль / состояние роли | Применяемая роль управления |
|---|---|---|---|
| Не вошёл | - | Not Logged / включена | Not Logged |
| Не вошёл | - | Not Logged / отключена | - |
| Вошёл | Роль назначена | Назначенная роль / включена | Назначенная роль |
| Вошёл | Роль назначена | Назначенная роль / отключена | - |
| Вошёл | Роль не назначена | Default / включена | Default |
| Вошёл | Роль не назначена | Default / отключена | - |

## Доступные разрешения

13 настраиваемых разрешений соответствуют разделу «Настройки → Безопасность → Разрешения» на управляемом устройстве:

- Клавиатура/мышь
- Удалённый принтер
- Буфер обмена
- Передача файлов
- Звук
- Камера
- Терминал
- TCP-туннель
- Удалённая перезагрузка
- Запись сеанса
- Блокировка ввода пользователя
- Изменение удалённой конфигурации
- Режим конфиденциальности

## Действия в консоли

### Создание роли

1. Откройте страницу **Control Roles** и нажмите **Create**
2. Введите **Name** (название роли)
3. Выберите **Permissions** (разрешения), которые нужно выдать

![](/docs/en/self-host/rustdesk-server-pro/control-role/images/control-role-create-name.png)
![](/docs/en/self-host/rustdesk-server-pro/control-role/images/control-role-create-permission.png)

### Назначение роли

Назначить роль управления пользователям можно двумя способами:

1. **Страница Users** → нажмите **Edit** у пользователя → выберите роль в поле **Control Role**
2. **Страница Control Roles** → нажмите на **число пользователей** или **Assign Users** → добавьте пользователей в роль или удалите их из неё

![](/docs/en/self-host/rustdesk-server-pro/control-role/images/control-role-assign-user-page.png)
![](/docs/en/self-host/rustdesk-server-pro/control-role/images/control-role-assign-role-page.png)

{{% notice note %}}
Роль «Not Logged» нельзя назначить пользователям (она действует только для подключений без входа в учётную запись).
{{% /notice %}}
