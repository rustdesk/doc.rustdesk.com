Роли администраторов нужны, когда в RustDesk Server Pro требуется делегировать часть прав управления, не выдавая полных прав администратора.

Роль администратора позволяет администраторам передавать часть прав управления пользователям без прав администратора. Можно задавать разрешения на глобальные ресурсы (например, стратегии, роли управления и собственные клиенты), а также на пользователей и устройства в разных областях.

Когда пользователю назначена роль администратора, он видит в веб-консоли страницы и меню, соответствующие выданным разрешениям.

## Когда использовать роль администратора?

Используйте роль администратора, когда кому-то нужно управлять частью вашей среды RustDesk, не становясь полноправным администратором. Это подходит для руководителей службы поддержки, региональных ИТ-отделов, владельцев устройств или операторов, которые должны управлять только частью парка устройств в рамках своих групп.

## Коротко о ролях администраторов

- Роли администраторов делегируют права управления в консоли
- Они не заменяют полноценные учётные записи администраторов
- У пользователя может быть несколько ролей администратора одновременно
- Итоговый набор разрешений — объединение всех назначенных ролей администратора
- Роли с групповой областью (Group Scoped) подходят, когда управление должно ограничиваться выбранными группами

## Администраторы и роли администраторов

- Изменять роли администраторов и назначать их пользователям могут только администраторы.
- На администраторов роли администраторов не распространяются, хотя назначить их администраторам можно.
- Пользователи без прав администратора не могут изменять учётные записи администраторов, даже если у них есть глобальные разрешения на пользователей.

## Типы ролей

Есть три типа ролей администратора, у каждого своя область действия и свой набор разрешений.

| Тип | Описание |
|------|-------------|
| **Global** | Может управлять всеми ресурсами всей команды |
| **Individual** | Может управлять только собственными устройствами и журналами аудита пользователя |
| **Group Scoped** | Может управлять пользователями и устройствами в указанных группах |

### О типе Group Scoped

| Выбранные разрешения | К чему применяются |
|-------|-------------|
| **User Permissions** | К пользователям в выбранных группах пользователей |
| **Device Permissions** | К устройствам из: <ul><li>выбранных групп устройств</li><li>устройств, назначенных пользователям в выбранных группах пользователей</li><li>неназначенных устройств (если включено)</li></ul> |

В роли Group Scoped можно выбрать только User Permissions или только Device Permissions, чтобы разрешения и область действия были понятнее. Например, если выбрать только User Permissions, роль сможет управлять пользователями без доступа к устройствам, а если только Device Permissions — управлять устройствами, выбрав областью группы пользователей, группы устройств или неназначенные устройства.

## Правила разрешений

### Любое разрешение на изменение включает соответствующее разрешение на просмотр

Любое разрешение на изменение автоматически включает соответствующее разрешение на просмотр. Например, разрешение «Devices Enable/Disable» включает разрешение «View Devices».

### Разрешение на изменение не включает назначение

Разрешения на изменение ресурсов (групп пользователей, групп устройств, стратегий, ролей управления) позволяют изменять только сами ресурсы, но не назначать их пользователям или устройствам.

Например, разрешение «Edit Device Groups» позволяет создавать и изменять группы устройств, но чтобы добавлять устройства в группы или удалять их из групп, нужно разрешение «Devices Update Group».

### Разрешение на просмотр не включает участников

Разрешения на просмотр ресурсов (групп пользователей, групп устройств, стратегий, ролей управления) позволяют просматривать только сами ресурсы, но не их участников.

Например, разрешение «View Device Groups» позволяет видеть список групп устройств, но чтобы видеть устройства внутри группы, нужно разрешение «View Devices» или любое разрешение на изменение устройств. Если разрешение на устройства глобальное, видны все устройства в группе; если оно групповое или индивидуальное — только устройства в пределах разрешённой области.

{{% notice note %}}
Чтение устройств для адресных книг ролями администраторов не ограничивается. Вкладка доступных устройств в клиенте управляется только настройкой консоли **Settings → Others → Disable retrieving accessible devices** и ролями администраторов тоже не ограничивается.
{{% /notice %}}

## Действия в консоли

### Создание роли

1. Откройте страницу **Admin Roles** и нажмите **Create**
2. Введите **Name** (название роли)
3. Выберите **Type** (тип; для **Group Scoped** также настройте область)
4. Выберите **Permissions** (разрешения), которые нужно выдать

![](/docs/en/self-host/rustdesk-server-pro/admin-role/images/admin-role-create-name.png)
![](/docs/en/self-host/rustdesk-server-pro/admin-role/images/admin-role-create-permission.png)

### Назначение роли

Назначить роли администратора пользователям можно двумя способами:

1. **Страница Users** → нажмите **Edit** у пользователя → выберите роли в поле **Admin Roles**
2. **Страница Admin Roles** → нажмите на **число пользователей** или **Assign Users** → добавьте пользователей в роль или удалите их из неё

![](/docs/en/self-host/rustdesk-server-pro/admin-role/images/admin-role-assign-user-page.png)
![](/docs/en/self-host/rustdesk-server-pro/admin-role/images/admin-role-assign-role-page.png)

{{% notice note %}}
- Пользователю можно назначить несколько ролей администратора. Разрешения всех назначенных ролей объединяются.
{{% /notice %}}
