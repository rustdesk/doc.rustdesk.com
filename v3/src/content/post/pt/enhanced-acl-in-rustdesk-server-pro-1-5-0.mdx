O RustDesk Server Pro 1.5.0 já está disponível, com grupos de dispositivos e controle de acesso por usuário.

## Registro de alterações

- Adicionados os grupos de dispositivos e suas regras de controle de acesso
- Adicionado o controle de acesso por usuário
- Adicionadas políticas para grupos de dispositivos
- Adicionadas tabelas ordenáveis
- O login via OIDC passa a ser vinculado a uma conta existente quando o e-mail coincide
- Permitido o uso de `-` (hífen) nos IDs de dispositivo
- Corrigida a falha de login quando o nome no OIDC é `null`

O recurso de grupos de dispositivos é uma novidade do RustDesk Server Pro 1.5.0. Antes, o RustDesk priorizava a simplicidade e evitava introduzir grupos de dispositivos, usando apenas grupos de usuários no gerenciamento de ACL (lista de controle de acesso). Essa abordagem, porém, tornava trabalhosa a configuração de permissões de acesso em organizações grandes. Por isso, decidimos introduzir os grupos de dispositivos e a ACL por usuário na versão 1.5.0. Essa melhoria permite agrupar dispositivos e aplicar políticas a esses grupos, o que melhora bastante o gerenciamento de dispositivos em ambientes de grande escala.

Originalmente, o RustDesk Server Pro só oferecia suporte a grupos de usuários; com esta atualização, ele passa a oferecer também grupos de dispositivos. Cada dispositivo pode ser atribuído a um único grupo de dispositivos, além de estar associado a um usuário. Isso permite aplicar políticas adicionais com base nos grupos de dispositivos, como restringir ou conceder acesso a dispositivos específicos. Além disso, esta versão introduz a ACL por usuário, que permite definir permissões para usuários individuais, além dos grupos de usuários, oferecendo mais flexibilidade e controle no gerenciamento de acesso.

**Atualização (2026):** versões posteriores do Server Pro acrescentaram a [Função de controle](https://rustdesk.com/docs/pt/self-host/rustdesk-server-pro/control-role/) para as permissões dentro da sessão. As permissões de grupos de usuários e de grupos de dispositivos são cumulativas, então qualquer uma delas pode conceder acesso. Para a configuração atual, veja a [documentação de Controle de acesso](https://rustdesk.com/docs/pt/self-host/rustdesk-server-pro/permissions/).
