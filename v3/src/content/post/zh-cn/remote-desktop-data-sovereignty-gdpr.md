如果你的组织受 GDPR、医疗隐私法规约束，或需要遵守公共部门“数据必须留在自有基础设施上”的强制要求，那么有一个问题将决定哪些远程桌面工具能进入候选名单：**会话数据究竟流向何处？**

在供应商托管的服务中，通常由供应商运营连接协调并存储管理/账户数据。会话媒体流可能在终端之间直接传输，也可能经过中继。数据流审查必须区分这些路径；“由云端协调”并不意味着每一个屏幕数据包都经过云端。

本指南讨论的是**远程桌面数据主权**：它意味着什么、为何对受监管行业及欧盟买家至关重要，以及自托管能让你掌控远程访问部署中的哪些环节。我们将以 RustDesk 作为具体案例来说明。

## “数据主权”对远程访问意味着什么

数据主权是指数据受其物理存储和处理所在国家/地区法律管辖的原则。对远程支持而言，敏感数据不只是你传输的文件——会话本身就是敏感数据：屏幕上显示的内容、你所管理的设备列表、连接元数据，以及像素数据实时传输所经过的路由。

核心问题在于：**哪些系统存储元数据，哪些系统中转流量，两端终端又分别位于何处？** 自托管可以把供应商运营的连接协调服务或中继服务从路径中移除，但无法保证分处不同国家的终端之间的会话始终留在同一司法辖区内。

## 核心差异：供应商云端与你自己的基础设施

在这一点上，决定结果的是架构本身，而非市场宣传。

**RustDesk Server Pro 是自托管的。** ID/连接协调服务器、中继服务器、Web 控制台和受管设备数据，都运行在你选择的基础设施上。RustDesk 会先通过打洞（hole punching）尝试建立直接的点对点连接；如果失败，会话流量会经过你配置的中继。这让你掌控连接协调/中继这一层以及存储的设备数据，但直连流量的走向仍取决于终端及其网络路由。

|                    | 供应商云端工具     | 自托管 RustDesk                                                                  |
| ------------------ | ------------------ | -------------------------------------------------------------------------------- |
| 会话在哪里协调     | 供应商的云端       | 你自己的 ID/连接协调服务器                                                       |
| 会话流量如何流动   | 由供应商定义的路由 | 尽可能在终端之间直连；否则经过你的中继                                           |
| 谁掌控数据驻留位置 | 供应商             | 你自行选择服务器端位置和中继策略；终端位置依然重要                               |
| 客户端的可审计性   | 通常为闭源         | [开源（AGPL）](https://github.com/rustdesk/rustdesk)——你可以自行阅读代码并构建 |
| 谁来运行服务器     | 供应商             | 你自己的团队                                                                     |

评估自托管的团队通常首先提到的就是这项控制权：自行选择连接协调、中继和管理系统的部署位置与运营方。

## 优势一：由你掌控服务器端的数据位置

把 ID、中继和管理服务部署在德国的数据中心，你就能明确记录这些服务及其存储数据的位置。再让两端终端都位于所要求的边界内，并强制流量经过批准的中继，你还能约束会话的路由。

## 优势二：开源意味着你可以验证客户端

RustDesk 的**客户端和 RustDesk Server OSS（免费社区服务器）采用 [AGPL 许可证](https://github.com/rustdesk/rustdesk)**；**Server Pro 是商业的专有自托管服务器软件**。你的安全团队可以阅读客户端代码，审计它在终端上的行为，并自行构建。这对远程访问而言格外重要：这类软件被授予完全控制一台机器的权限，受监管的买家也越来越希望亲自验证客户端的行为，而不是轻信供应商的说法。

## 优势三：不同的服务器授权模式

RustDesk 标准套餐按**登录用户加受管设备**授权，并包含无限并发连接；只有 [Customized V2](https://rustdesk.com/pricing#custom2) 授权固定数量的并发连接。需求变化时，你可以随时[升级许可证](/zh-cn/blog/upgrade-rustdesk-license-mid-subscription-zh-cn)。

这一模式会随设备规模扩展：[大规模设备部署规划指南](/zh-cn/blog/rustdesk-scale-50000-200000-devices-zh-cn)覆盖多达 20 万台设备的部署。Server Pro 增加了按用户和设备组设定的[访问控制](https://rustdesk.com/docs/zh-cn/self-host/rustdesk-server-pro/permissions/)，并从 Basic 套餐起提供 LDAP/OIDC 单点登录和自定义客户端生成。

## RustDesk 如何契合 ISO 27001、SOC 2 或 HIPAA 要求

企业采购和医疗团队几乎总会问：一款远程访问工具如何对应 ISO 27001、SOC 2 或 HIPAA？使用云产品时，你依赖的是供应商对其自身基础设施的认证及其责任共担条款。自托管的 RustDesk 正好相反：ID/连接协调服务、中继和控制台运行在你的合规体系已经覆盖的基础设施上，因此你可以在自己的 ISO 27001 范围、SOC 2 控制或 HIPAA 保障措施下评估它们，安全团队也可以在评估中检查客户端源代码。自托管是一种部署控制手段，而不是认证；真正把它纳入合规范围的是评估本身。

几点实用说明：

- 自托管让你自行选择连接协调、中继、控制台和存储的管理数据的位置与运营方。请把终端路由、备份和管理员访问与这些位置一并记录。
- 如果你的采购明确要求供应商提供 SOC 2 报告、签署业务伙伴协议（BAA）、DPA 或填写安全问卷，请联系 RustDesk 团队 [sales@rustdesk.com](mailto:sales@rustdesk.com)，了解针对你的场景目前可提供哪些资料。
- 由于客户端开源，“我们怎么知道它做了什么？”这个问题可以通过检查代码来回答；供应商保证报告回答的是另一个采购问题。

简而言之，自托管把远程访问纳入你已经在运行的合规体系之中。对受监管团队来说，这往往比依赖供应商对你无法检查的基础设施所做的认证更有底气。

## 支撑自托管 GDPR 合规体系的控制措施

自托管是基础，在此之上，RustDesk 还提供了自托管团队在 GDPR 合规体系中所依赖的具体控制措施：

- **服务器数据留在你部署的位置，对外工作流只有少数几项。** 自托管的 ID/连接协调服务、中继和 Pro 管理服务在你运行它们的地方处理部署数据。需要记录的对外工作流包括：Pro 许可证验证（大约每天一次通过 HTTPS 连接 rustdesk.com）、自定义客户端构建服务、客户端更新、配置外部邮件服务器时的 SMTP，以及你接入的任何外部身份提供商。参见 [Server Pro 离线与气隙部署指南](/zh-cn/blog/rustdesk-server-pro-offline-air-gapped-zh-cn)。
- **可配置的审计日志保留。** [Server Pro 审计日志](https://rustdesk.com/docs/zh-cn/self-host/rustdesk-server-pro/audit-logs/#日志可见性和保留)涵盖连接、文件传输、告警和控制台操作。在 **设置 → 其他 → 日志保留（天）** 中，`0` 表示无限期保留所有日志；设为正数则删除更早的日志，清理每小时执行一次。导出和备份的保留期限需另行规定。
- **精细、有边界的访问权限。** [访问控制](https://rustdesk.com/docs/zh-cn/self-host/rustdesk-server-pro/permissions/)通过按用户分配、设备组和跨组规则，决定谁能访问哪些设备（用户组和设备组的权限会累加）。共享通讯录只用于组织条目，不构成访问边界。[控制角色](https://rustdesk.com/docs/zh-cn/self-host/rustdesk-server-pro/control-role/)限制技术人员在会话中可以执行的操作——键盘/鼠标、剪贴板、文件传输、音频、摄像头、终端、打印、录制等。结合 SSO/LDAP 和受控设备 2FA，它们共同落实最小权限和目的限制原则。
- **隐私模式与逐次连接确认。** 被控端可以要求对每次入站连接进行确认；隐私模式（支持 Windows 和 macOS）会在会话期间让本地屏幕黑屏，减少屏幕上个人数据的意外暴露。
- **按你的方式删除数据。** 由于数据存放在你的服务器上，你可以禁用或移除用户、删除设备和记录（包括通过 REST API），并直接处理擦除和保留请求。
- **区域内自主运营的基础设施。** ID/连接协调服务、中继、控制台和存储的数据，都运行在你部署的位置、你掌控的硬件上。
- **自定义客户端构建是临时性的。** 生成品牌客户端是唯一使用 RustDesk 构建服务的步骤，而且被刻意设计为短时处理：你提交的构建配置会在构建完成后删除，生成的安装包约一天后自动移除，因此请及时下载，并保存在你自己批准的存储库中。

这些都是 GDPR 合规体系能够切实运用的手段：你仍需记录并执行它们，但不必等待供应商来处理数据主体的请求。

## 看得见、摸得着的主权

自行托管连接协调服务、中继、控制台和存储的数据，能为合规体系提供实实在在的支撑：由你部署、运营和审计的基础设施。这是起点而非终点，却是其他一切赖以建立的根基。

## GDPR 与数据主权部署清单

自托管给了你选择；部署工作则要把这些选择转化为切实的控制措施：

- 记录 ID 服务器、中继服务器、控制台、备份、日志以及管理员分别位于何处。
- 分别梳理点对点直连路由和经中继转发的路由。位于德国的服务器，并不能让德国与另一国之间的直连会话始终留在德国境内。
- 明确在哪些情况下必须强制使用中继——即流量必须经过受控位置比点对点性能更重要的时候。
- 记录设备、账户、审计和连接元数据各自的处理目的、保留期限和访问策略。
- 对设备组落实最小权限原则，在条件允许时启用 MFA/SSO，并为技术人员建立入职-调岗-离职（joiner-mover-leaver）流程。
- 将 Web 控制台置于 HTTPS 之后，限制管理网络的访问，并测试备份恢复。
- 根据你的使用场景完成相应的法律评估，例如处理活动记录、处理者审查、数据传输评估以及数据保护影响评估（DPIA）。

RustDesk 可以为主权架构提供支撑，但架构本身及其法律依据的责任，始终由数据控制者承担。
