2026 年 7 月 7 日，RustDesk 內部遙測在一台配備 **12 核心 CPU 與 32 GB 記憶體**的公用伺服器主機上，記錄到**超過兩百萬個線上端點**。

有兩點界定了它的範圍。第一，「線上端點」是指在那個時間點回報為線上的裝置，而不是兩百萬個同時進行的遠端控制工作階段。第二，這是一次內部正式環境的觀察，不是經獨立稽核的基準測試，也不是 Server Pro 的保證：Server Pro 部署還會增加資料庫寫入、稽核活動、主控台使用、原則處理與中繼流量。

## 簡短回答

**20 萬台線上裝置是 Server Pro 切合實際的規劃目標。** 上述公用伺服器的觀察結果，在單台 12 核心、32 GB 的主機上就比這個目標高出一個數量級。您要在試行中驗證的，是 Server Pro 在端點上線之外額外增加的負載：裝置異動、原則、稽核寫入、主控台使用，以及同時進行的中繼工作階段。

## 詳細說明

對於正從 TeamViewer 或 AnyDesk 遷移出來的 IT 團隊，擴展性是我們最常聽到的問題之一，尤其是正在規劃數萬甚至數十萬台裝置群的團隊。答案取決於有多少裝置維持上線、裝置狀態變動的頻率、同時執行的遠端工作階段數，以及有多少流量經過中繼伺服器。

在 Server Pro 部署中，請驗證公用伺服器數字沒有涵蓋的部分。裝置不斷上線、離線時，快取與資料庫寫入效能就很重要。中繼頻寬與 CPU 取決於同時中繼工作階段的數量、時長、解析度與編解碼器。主控台查詢、稽核保留、裝置群組、原則與整合，會增加光看端點上線數無法衡量的負載。請在具代表性的負載測試中，納入預期的上線數、連線異動、同時進行的直連與中繼工作階段、資料庫保留設定與管理活動。

為了進行可重複的 Server Pro 試行，請記錄用戶端／伺服器版本、硬體、資料庫與中繼的配置位置。分階段增加上線裝置數與異動，同時執行預期的主控台查詢、原則更新與稽核寫入。量測註冊／重新連線成功率、連線建立時間、資料庫延遲、CPU／記憶體、磁碟成長與中繼吞吐量。也請納入尖峰同時工作階段與一次復原演練；這些量測結果請與線上端點數分開記錄。

高可用性與負載平衡也應比照辦理。中繼伺服器可以橫向擴展：您可以執行多台、依區域配置，而且 hbbr 中繼伺服器不需要授權。一份 Pro 授權綁定一台 hbbs 伺服器，所以請明確設計 ID 伺服器與資料庫的容錯移轉，並在裝置群非常龐大時與 RustDesk 一起檢視。

接著再計算授權：Server Pro 依登入使用者與受管裝置授權，標準方案不限同時連線數。請到 [rustdesk.com/pricing](https://rustdesk.com/pricing) 選擇適合您裝置群的方案。
