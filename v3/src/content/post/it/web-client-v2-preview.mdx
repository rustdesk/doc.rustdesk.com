A ottobre 2024 abbiamo presentato l'**anteprima del client web RustDesk V2**. Porta una decodifica più efficiente, un supporto migliore per le tastiere internazionali, gli appunti per immagini oltre che per il testo e il trasferimento file. Abbiamo lavorato per mantenere funzionalità ed esperienza d'uso della versione web allineate a quelle del client desktop, nei limiti imposti dai browser.

Puoi accedere all'anteprima del client web RustDesk V2 visitando https://rustdesk.com/web. Se vuoi accedere al tuo server tramite V2, configura il supporto WebSocket Secure (WSS) seguendo la [documentazione](https://rustdesk.com/docs/it/self-host/rustdesk-server-pro/faq/#8-aggiungere-supporto-websocket-secure-wss-per-il-server-id-e-il-server-relay-per-abilitare-la-comunicazione-sicura-su-tutte-le-piattaforme), cioè inoltrando tramite HTTPS/WSS i backend WebSocket dell'ID e del relay sulle porte 21118/21119. Quando il reverse proxy espone la porta TCP 443, mantieni queste porte di backend accessibili solo internamente.

```nginx
    location /ws/id {
        proxy_pass http://localhost:21118;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws/relay {
        proxy_pass http://localhost:21119;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
```

Il client web è inoltre **integrato in RustDesk Server Pro**, quindi puoi servirlo dal tuo server all'indirizzo `https://rustdesk.yourcompany.com/web` invece di affidarti a quello pubblico.

## Due modi per usare il client web con il tuo server

- **Client web pubblico (`rustdesk.com/web`) collegato al tuo server.** Puoi usare il client web ospitato da RustDesk e collegarlo al tuo server ID/relay, ma la configurazione è a tuo carico: il browser ha bisogno di WebSocket Secure (WSS) e delle intestazioni CORS corrette per raggiungere il tuo server. Vedi [Configurazione WSS e CORS per il client web](https://github.com/rustdesk/rustdesk/wiki/FAQ#wss-and-cors-setup-for-web-client).
- **Client web self-hosted (servito da Server Pro all'indirizzo `https://your-server/web`).** Il client web è [integrato in RustDesk Server Pro](https://github.com/rustdesk/rustdesk/wiki/FAQ#is-web-client-integrated-into-rusetdesk-server-pro), quindi gira sul tuo server invece che su quello pubblico. Il self-hosting del client web **non è incluso nei piani d'ingresso**: richiede un piano abbastanza ampio da soddisfare **(numero di utenti × 10) + numero di dispositivi ≥ 400** (ad esempio 10 utenti / 300 dispositivi, 30 utenti / 100 dispositivi o 20 utenti / 200 dispositivi). Un client web self-hosted può anche essere [personalizzato](https://github.com/rustdesk/rustdesk/wiki/FAQ#how-to-customize-self-hosted-web-client).

Qualunque strada tu scelga, il client web è un **controller**: puoi controllare altri dispositivi da una scheda del browser, ma una scheda del browser non può fare da host non presidiato.

Prova oggi stesso il [client web](https://rustdesk.com/web) e consulta la [documentazione di Server Pro](https://rustdesk.com/docs/it/self-host/rustdesk-server-pro/) per i dettagli di implementazione aggiornati. I permessi degli appunti e la gestione della tastiera variano da un browser all'altro, quindi prova quelli che usa il tuo team.
