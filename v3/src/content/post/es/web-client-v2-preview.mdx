En octubre de 2024 presentamos la **vista previa del cliente web RustDesk V2**. Trae una decodificación más potente, mejor compatibilidad con teclados internacionales, portapapeles para imágenes además de texto, y transferencia de archivos. Trabajamos para mantener las funciones y la experiencia de uso de la versión web a la par del cliente de escritorio, dentro de los límites que imponen los navegadores.

Puedes acceder a la vista previa del cliente web RustDesk V2 en https://rustdesk.com/web. Si quieres acceder a tu propio servidor a través de V2, configura la compatibilidad con WebSocket Secure (WSS) según la [documentación](https://rustdesk.com/docs/es/self-host/rustdesk-server-pro/faq/#8-add-websocket-secure-wss-support-for-the-id-server-and-relay-server-to-enable-secure-communication-for-all-platforms) y pon los backends WebSocket del servidor de ID y del relay, en los puertos 21118/21119, detrás de un proxy HTTPS/WSS. Mantén esos puertos internos cuando el proxy inverso exponga el puerto TCP 443.

```nginx
    location /ws/id {
        proxy_pass http://localhost:21118;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws/relay {
        proxy_pass http://localhost:21119;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
```

El cliente web también está **integrado en RustDesk Server Pro**, así que puedes servirlo desde tu propio servidor en `https://rustdesk.yourcompany.com/web` en lugar de depender del público.

## Dos formas de usar el cliente web con tu propio servidor

- **Cliente web público (`rustdesk.com/web`) apuntando a tu servidor.** Puedes usar el cliente web alojado por RustDesk y conectarlo a tu propio servidor de ID/relay, pero lo configuras tú: el navegador necesita WebSocket Secure (WSS) y las cabeceras CORS correctas para llegar a tu servidor. Consulta [Configuración de WSS y CORS para el cliente web](https://github.com/rustdesk/rustdesk/wiki/FAQ#wss-and-cors-setup-for-web-client).
- **Cliente web autoalojado (servido por Server Pro en `https://your-server/web`).** El cliente web está [integrado en RustDesk Server Pro](https://github.com/rustdesk/rustdesk/wiki/FAQ#is-web-client-integrated-into-rusetdesk-server-pro), así que se ejecuta desde tu propio servidor y no desde el público. Autoalojar el cliente web **no está incluido en los planes de entrada**: requiere un plan lo bastante grande como para cumplir **(número de usuarios × 10) + número de dispositivos ≥ 400** (por ejemplo, 10 usuarios / 300 dispositivos, 30 usuarios / 100 dispositivos o 20 usuarios / 200 dispositivos). Un cliente web autoalojado también se puede [personalizar](https://github.com/rustdesk/rustdesk/wiki/FAQ#how-to-customize-self-hosted-web-client).

Elijas la vía que elijas, el cliente web es un **controlador**: manejas otros dispositivos desde una pestaña del navegador, pero una pestaña del navegador no puede actuar como host desatendido.

Prueba hoy mismo el [cliente web](https://rustdesk.com/web) y consulta la [documentación de Server Pro](https://rustdesk.com/docs/es/self-host/rustdesk-server-pro/) para conocer los detalles de despliegue actuales. Los permisos del portapapeles y la gestión del teclado varían de un navegador a otro, así que prueba los que usa tu equipo.
