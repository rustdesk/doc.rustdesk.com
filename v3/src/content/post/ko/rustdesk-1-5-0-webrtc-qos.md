최근 실제 사용 경험을 공유했습니다. 1.5.0으로 업그레이드한 뒤 다른 대륙에서 집에 있는 Mac에 접속했을 때 이전보다 더 부드럽게 사용할 수 있었습니다. [원문](https://x.com/rustdesk/status/2110243829978898520)은 이 사용 경험을 기록한 것입니다. 아래에서는 1.5.0의 연결 방식과 화면 전송 적응 제어에 적용된 구체적인 변경 사항을 소개합니다.

[PR #15684](https://github.com/rustdesk/rustdesk/pull/15684)는 WebRTC Data Channel을 도입해 ICE 연결 시도를 기존 TCP 및 UDP 홀 펀칭, IPv6 직접 연결 경로와 병렬로 진행하도록 했습니다. 릴레이 연결이 준비되었지만 직접 연결 시도가 아직 진행 중이면 RustDesk는 잠시 직접 연결을 우선하는 시간을 둡니다. 이 시간이 끝나거나 직접 연결 시도가 실패하면 릴레이를 사용할 수 있습니다. 이를 통해 이전에는 릴레이가 필요했던 일부 연결에서도 직접 연결할 기회가 생깁니다.

**웹 클라이언트도 이제 직접 연결을 지원합니다.** 이전에는 브라우저의 RustDesk 세션이 반드시 릴레이 서버를 거쳐야 했습니다. 이제 네트워크 조건이 허용하고 ICE가 직접 경로를 선택하면 브라우저와 원격 기기 사이에서 세션 데이터를 직접 전송할 수 있어 릴레이 경로의 지연과 대역폭 제한을 피할 수 있습니다. TURN을 통해 전달되는 WebRTC 연결은 여전히 릴레이 연결입니다. 이번 통합은 Data Channel로 RustDesk 프로토콜을 전송하며, 영상 인코딩과 디코딩은 계속 RustDesk가 처리합니다.

QoS 변경은 [PR #16082](https://github.com/rustdesk/rustdesk/pull/16082)에서 이루어졌습니다. 기존 정책은 한 번의 느린 응답이나 짧은 정체만으로 프레임 레이트를 크게 낮추고 이후에는 천천히 복원하는 문제가 있었습니다. 1.5.0의 조정 사항은 다음과 같습니다.

- **지연 기준값 개선.** 첫 응답부터 각 연결의 낮은 지연 기준값을 사용하고, 안정적인 기준값 변화에 점진적으로 적응해 지연이 높은 링크에서의 오판을 줄입니다.
- **일반적인 지연 변동은 먼저 확인.** 일반적인 프레임 레이트 감소에는 연속 세 번의 비정상 응답을 통한 확인이 필요합니다. 다만 심각한 추가 지연이나 프로브 시간 초과는 더 빠른 프레임 레이트 감소를 유발할 수 있습니다.
- **조건이 허용하면 비트레이트를 먼저 조정.** 일반적인 혼잡 조정에서는 적응형 비트레이트가 활성화되어 있고 비트레이트를 더 낮출 수 있을 때 비트레이트를 먼저 낮춥니다. 목표 비트레이트를 유지하는 인코더에 대해 프레임 수 감소에만 의존해 대응하는 상황을 피하기 위한 것입니다.
- **시작 시 목표 상승과 목표 프레임 레이트 복원 가속.** 상태가 양호한 링크에서 추가 지연이 적은 응답이 연속 두 번 오면 시작 시 목표값을 더 빠르게 높일 수 있습니다. 혼잡 이후에는 두 번의 양호한 응답으로 이전 목표 프레임 레이트를 복원할 수 있습니다. 복원 직후 혼잡이 다시 발생하면 제어기는 복원한 목표값을 되돌립니다.

이 정책들은 화면 전송과 같은 전송 경로를 사용하는 지연 피드백을 활용합니다. 이 피드백에는 전송 적체, 네트워크 왕복 시간, 클라이언트 응답 스케줄링 등의 영향이 포함됩니다. 부하 변화를 판단하는 데 사용하며, 큐잉 지연만 따로 측정하는 것은 아닙니다. [1.5.0 QoS 구현](https://github.com/rustdesk/rustdesk/blob/1.5.0/src/server/video_qos.rs)

시작 시 가속을 위한 변경에 대해 PR 작성자는 로컬 링크의 사무 작업 시나리오 테스트에서 해당 변경을 적용한 커밋과 그 부모 커밋을 비교했습니다. 이 테스트에서 **목표값이 60 FPS에 도달하기까지** 걸리는 시작 시간이 **7.99초에서 2.98초로 줄었습니다**. 이는 해당 변경이 이 테스트의 시작 시 목표 프레임 레이트 상승 속도에 미친 영향을 측정한 결과입니다. [테스트 기록](https://github.com/rustdesk/rustdesk/pull/16082#issuecomment-5597385117)

[RustDesk 1.5.0](https://github.com/rustdesk/rustdesk/releases/tag/1.5.0)으로 업그레이드하거나 [웹 클라이언트](https://rustdesk.com/web)에서 새로운 연결 방식을 사용해 보세요. WebRTC를 사용하려면 연결 양쪽과 서버가 모두 지원해야 합니다. 자체 호스팅 서버에서는 이 옵션이 기본적으로 꺼져 있으므로 `enable-webrtc=Y`를 명시적으로 활성화해야 합니다. Server Pro의 경우 공식 문서에는 1.8.7 버전부터 지원한다고 안내되어 있습니다. 구성 방법은 [설정 안내](https://rustdesk.com/docs/en/self-host/client-configuration/advanced-settings/#enable-webrtc)를 참고하세요.
