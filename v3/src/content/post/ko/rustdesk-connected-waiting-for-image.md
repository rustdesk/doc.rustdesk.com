RustDesk에 **"연결됨, 화면을 기다리는 중..."**(Connected, waiting for image)이 표시된 뒤 검은 화면만 보인다면, 어려운 부분은 이미 성공한 것입니다. 양쪽 기기가 서로를 찾았고 세션도 연결되었습니다. 빠진 것은 _화면_ 입니다. 대부분은 원격 컴퓨터에 캡처할 화면이 없기 때문이고, 그보다 드물게는 코덱, GPU 드라이버, 릴레이 경로 때문에 스트림이 멈춥니다. 이 가이드에서는 가장 많이 보고되는 원인부터 드문 예외까지 하나씩 살펴보고, 각각의 구체적인 해결책을 제시합니다.

## 짧은 답변

세션은 연결되었지만 화면 이미지가 도착하지 않는 상태입니다. 가장 많이 보고되는 원인은 원격 컴퓨터에 캡처할 화면이 없는 경우로, **모니터가 없거나, 디스플레이가 절전 상태이거나, 화면 기록 권한이 없는 경우**입니다. RustDesk에 실제로 켜져 있는 디스플레이(모니터, HDMI 더미 플러그, 가상 디스플레이)와 올바른 권한을 제공하고, 그래도 화면이 나오지 않으면 VP9 같은 다른 코덱으로 바꿔 보세요. 그래도 검은 화면이 계속되면 GPU 드라이버를 업데이트하고 릴레이 포트에 접근할 수 있는지 확인하세요.

## 시작하기: 캡처할 대상이 있나요?

가장 많이 보고되는 원인은 **헤드리스 컴퓨터**입니다. 모니터 없이 실행되거나 디스플레이가 절전 상태인 서버, 미니 PC, 워크스테이션을 말합니다. 활성 디스플레이가 없으면 캡처할 프레임버퍼가 없는 경우가 많아, RustDesk는 연결은 되지만 보낼 것이 없습니다. 이 패턴은 RustDesk 이슈 트래커에 반복해서 나타나며, [대상 기기의 모니터가 꺼져 있을 때 검은 화면이 나온다는 보고](https://github.com/rustdesk/rustdesk/issues/9884)와 오래 이어진 ["Connected, waiting for image" 스레드](https://github.com/rustdesk/rustdesk/issues/222)가 대표적입니다.

캡처할 대상을 마련하는 방법은 두 가지입니다.

- **모니터를 연결**하고 전원이 켜져 있으며 절전 상태가 아닌지 확인하세요.
- **HDMI(또는 DisplayPort) 더미 플러그를 사용하세요.** 이 저렴한 어댑터는 GPU가 디스플레이가 연결되어 있다고 인식하게 만들어, RustDesk가 가져갈 프레임버퍼를 계속 렌더링하게 합니다. 헤드리스 데스크톱과 홈 서버의 표준 해결책입니다.

모니터가 _연결되어 있다면_, 다음으로 의심할 것은 디스플레이가 절전 상태로 들어갔는지입니다.

### 화면 절전, 잠금, 화면 보호기

전에는 잘 되다가 컴퓨터를 한동안 쓰지 않은 뒤 검은 화면이 나온다면 디스플레이가 절전 상태로 들어간 것입니다.

- **Windows:** 원격 접속이 필요한 시간대에는 디스플레이와 컴퓨터가 절전 상태로 들어가지 않도록 전원 관리 옵션을 설정하세요. RustDesk를 서비스로 설치하면 잠금 화면에서도 접속할 수 있으므로, 비밀번호로 보호되는 잠금은 계속 켜 두세요.
- **macOS:** 원격 접속이 필요한 시간대에는 디스플레이가 절전 상태로 들어가지 않게 하세요. **시스템 설정 → 디스플레이**(또는 잠금 화면/에너지 설정)에서 설정할 수 있으며, 배터리로 작동할 때는 절전 동작이 달라지므로 Mac을 전원 어댑터에 연결해 두세요.
- **Android:** 화면이 켜져 있어야 공유할 수 있으므로, 연결하기 전에 화면을 터치해 깨우세요. 화면이 꺼진 채 대기 중인 Android 기기에 iOS에서 연결하는 경우는 [알려진 "waiting for image" 사례](https://github.com/rustdesk/rustdesk/issues/11479)이므로, 먼저 대상 기기를 깨우세요.

### macOS 권한

macOS는 명시적인 동의 없이는 어떤 앱도 화면을 기록하지 못하게 합니다. Mac에서 RustDesk가 연결은 되지만 계속 검은 화면이라면 **시스템 설정 → 개인정보 보호 및 보안 → 화면 기록**에서 RustDesk를 허용한 다음 앱을 다시 시작하세요. 특히 _로그인 화면에서만_ 검은 화면이 나온다면, 사용자가 로그인하기 전에 실행되어야 하는 RustDesk 서비스/헬퍼가 설치되지 않은 것입니다. 로그인 전 화면을 캡처하려면 이를 설치하세요.

### 비디오 코덱 불일치

RustDesk는 여러 방식으로 스트림을 인코딩할 수 있으며, 기본값이 원격 하드웨어에 늘 맞는 것은 아닙니다. 세션 툴바(또는 설정)에서 **VP8, VP9, AV1, 그리고 하드웨어가 지원하는 경우 H.264/H.265**로 코덱을 바꿔 가며 화면이 나오는지 확인하세요. 특정 GPU에서 하드웨어 코덱이 빈 화면을 만든다면 VP9 같은 소프트웨어 코덱으로 돌아가는 것이 확실한 방법입니다.

### 하드웨어 가속과 GPU 드라이버

일부 GPU(가장 자주 언급되는 것은 NVIDIA 구성)는 RustDesk의 하드웨어 가속 캡처 및 렌더링 경로와 충돌합니다. 다음 두 가지가 도움이 됩니다.

- **하드웨어 코덱을 끄세요.** 세션 툴바(또는 설정)에서 **하드웨어 코덱 활성화**(Use hardware codec)를 끄면 인코딩이 소프트웨어 경로로 바뀌며, 문제가 있는 많은 GPU에서 검은 화면이 해결됩니다.
- **GPU 드라이버를 업데이트하세요.** 드라이버나 OS 업데이트 뒤에 시작된 검은 화면은 최신 드라이버로 바꾸면 해결되는 경우가 많으며, 특히 NVIDIA 하드웨어에서 그렇습니다.

### Linux와 Wayland

Linux에서 표준 RustDesk 빌드는 로그인된 세션에서 **PipeWire와 `xdg-desktop-portal`** 기반으로 Wayland 데스크톱을 캡처하며, 1.4.3부터는 다중 모니터도 지원합니다. 포털은 공유할 디스플레이를 고르라고 묻고, 포털 v4 이상은 그 선택을 기억할 수 있습니다. Wayland에서 빈 화면이 나오면 포털의 화면 공유 창을 수락하고 `xdg-desktop-portal`과 PipeWire가 설치되어 실행 중인지 확인하세요. 배포판이 아직 X11/Xorg 세션을 제공한다면 X11 세션으로 로그인해 포털 경로를 피할 수도 있습니다. 표준 빌드는 로그인된 세션을 캡처하므로 로그인 화면(그리터)에서 검은 화면이 나오는 것은 정상입니다. **x86_64 Debian/Ubuntu 계열 시스템**용 별도 [Wayland 무인 접속 프리뷰](/ko/blog/unattended-remote-access-wayland-ko)는 무인 접속과 재부팅 후 로그인 화면 접속을 추가합니다.

### 네트워크와 릴레이

메시지에 "연결됨"이라는 말이 들어 있는 만큼 세션 자체는 대개 이미 연결된 상태입니다. 하지만 릴레이가 과부하 상태이거나 릴레이 포트가 차단되어 있으면 _비디오_ 는 여전히 멈출 수 있습니다. 표준 서버 경로에서는 **TCP 21115-21117과 UDP 21116**에 처음부터 끝까지 도달할 수 있는지 확인하세요. **TCP 21118-21119는 WebSocket 클라이언트를 쓰는 경우에만** 여세요. 공개 데모 서버는 여러 사용자가 함께 쓰며 처리량이 보장되지 않으므로, RustDesk를 매일 쓴다면 릴레이를 자체 호스팅해 용량과 모니터링을 직접 통제하는 것이 좋습니다. 세션 자체가 끊기거나 아예 연결되지 않는다면 다른 문제이므로 [RustDesk Server Pro FAQ](https://rustdesk.com/docs/ko/self-host/rustdesk-server-pro/faq/)를 참고하세요.

## 모든 것을 최신 상태로 유지하세요

오래된 빌드에는 오래된 캡처 버그가 남아 있습니다. 제어하는 클라이언트와 제어받는 클라이언트를 **모두** 최신 릴리스로 업데이트하고, 자체 호스팅 중이라면 서버도 함께 업데이트하세요. 양쪽을 업데이트하는 것만으로 검은 화면이 사라진 보고가 여럿 있습니다.

## 오픈소스의 강점

체크리스트로도 검은 화면이 해결되지 않을 때, RustDesk는 비공개 소스 도구가 줄 수 없는 것을 제공합니다. 바로 AGPL 라이선스로 공개된 실제 캡처 코드입니다. 직접(또는 외부 개발자를 통해) 사용 중인 플랫폼에서 캡처가 어떻게 작동하는지 읽어 보고, 문제를 재현하고, 공개 저장소에 정확한 리포트를 올릴 수 있습니다. 공급사의 지원 대기열에서 기다릴 필요가 없습니다.

## 서버를 직접 운영하면 변수가 줄어듭니다

[릴레이 서버와 ID 서버를 직접 운영](/ko/blog/why-self-host-remote-desktop-software-ko)하면 공유 공용 인프라라는 변수가 사라집니다. 캡처 문제를 추적할 때 모르는 요소가 하나 줄고, 조정할 수 있는 부분을 완전히 통제할 수 있습니다. 데이터를 직접 보관하는 것에 더해 얻는 조용한 이점입니다.
