무인 접속이란 아무도 앞에 앉아 있지 않은 컴퓨터에 접속하는 것을 말합니다. 랙에 있는 서버, 키오스크, 먼 지역에 사는 가족의 PC 같은 경우입니다. RustDesk는 두 가지만 갖춰지면 무인 접속을 잘 처리합니다. 매번 누군가 연결을 승인할 필요가 없도록 하는 **영구 비밀번호**, 그리고 로그인 전과 로그아웃 후에도 쓸 수 있도록 **서비스로 실행**되는 RustDesk입니다. 이 가이드에서는 이 두 가지와 플랫폼별 권한, 그리고 여러 기기에 배포하는 방법을 다룹니다.

## 핵심 요약

**영구 비밀번호**를 설정하고(설정 → 보안), 컴퓨터와 함께 시작되는 **시스템 서비스로 RustDesk를 설치**하세요. 기본 승인 모드는 이미 영구 비밀번호를 허용하므로 누군가 수락을 클릭할 필요가 없고, 서비스는 로그인한 사용자와 무관하게 실행되므로 Windows 로그인 화면을 포함해 언제든 접속할 수 있습니다. macOS에서는 화면 기록과 손쉬운 사용 권한도 필요합니다. 대규모로 배포하려면 사전 구성된 클라이언트를 생성해 모든 컴퓨터가 자체 서버를 대상으로 설치되게 하세요.

## 1단계: 영구 비밀번호 설정

기본적으로 RustDesk는 주기적으로 바뀌는 일회용 비밀번호를 표시하며, 원격지에 있는 사람이 이를 불러 줘야 합니다. 무인 접속을 하려면 이를 고정된 자격 증명으로 바꿔야 합니다.

1. 접속하려는 컴퓨터에서 RustDesk를 엽니다.
2. **설정 → 보안**으로 이동합니다(이전 빌드에서는 메인 화면의 비밀번호 영역).
3. **영구 비밀번호 설정**을 선택하고 강력하고 고유한 값을 입력합니다.

기본 설정은 이미 이 비밀번호를 허용합니다. 세션은 비밀번호와 클릭 두 가지 방법으로 모두 수락되며, 두 종류의 비밀번호를 모두 쓸 수 있습니다. 누군가 승인 모드를 클릭 전용으로, 또는 비밀번호 유형을 일회용 전용으로 바꿨다면 **비밀번호를 통해 세션 수락**(또는 **두 가지 방법을 통해 세션 수락**)과 **영구 비밀번호 사용**(또는 **두 가지 비밀번호 모두 사용**)으로 되돌리세요. 관리형 배포에서 이에 해당하는 [설정 키](https://rustdesk.com/docs/ko/self-host/client-configuration/advanced-settings/#승인-모드)는 `approve-mode`(기본값 `password-click`)와 `verification-method`(기본값 `use-both-passwords`)입니다.

[RustDesk 클라이언트 문서](https://rustdesk.com/docs/ko/client/)에서도 이를 무인 접속의 핵심으로 설명합니다. 특히 강조할 규칙이 하나 있습니다. **운영체제 로그인 비밀번호를 재사용하지 마세요.** RustDesk 전용의 엔트로피가 높은 비밀번호를 쓰면, 한쪽 자격 증명이 유출되어도 다른 쪽까지 위험해지지 않습니다.

## 2단계: 서비스로 설치하고 부팅 시 시작

많은 사람이 놓치는 단계입니다. 포터블 `.exe`나 `.app`은 사용자 세션 안에서 실행되므로 사용자가 로그아웃하면 멈추며, Windows에서는 권한 상승 없이 UAC 보안 데스크톱을 조작할 수 없습니다(사용자가 자리에 있는 지원에는 [포터블 권한 상승](https://rustdesk.com/docs/ko/client/windows/windows-portable-elevation/)을 쓸 수 있습니다). 진정한 무인 접속을 하려면 RustDesk가 백그라운드 **시스템 서비스**로 실행되어야 합니다.

- 포터블 빌드가 아닌 RustDesk **설치 파일**을 실행해 설치를 마칩니다.
- **설정 → 일반**에서 **서비스**가 실행 중인지 확인하고, 중지 상태로 표시되면 **시작**을 누릅니다. 설치가 끝나면 서비스는 컴퓨터와 함께 자동으로 시작됩니다.

RustDesk가 서비스로 실행되면 누군가 로그인하기 전에 이미 로드되어 있으므로, **로그인 화면**에 접속해 원격으로 인증하고, 사람이 없어도 재부팅 후 다시 연결할 수 있습니다. macOS와 Linux에는 화면 캡처와 디스플레이 세션에 관한 별도 요구 사항이 있으며, 아래에서 다룹니다.

## 플랫폼별 참고 사항

| 플랫폼  | 해야 할 일                                     | 주의할 점                                                                                                                                         |
| ------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows | 설치 후 서비스 실행 유지(컴퓨터와 함께 시작)   | 포터블 exe는 로그아웃 시 멈추고 권한 상승 없이는 UAC 창을 조작할 수 없으므로 설치 파일 사용                                                       |
| macOS   | 설치, 영구 비밀번호 설정, 권한 부여            | 화면 기록과 손쉬운 사용 권한을 반드시 부여해야 하며, 로그인 화면 캡처에는 헬퍼 설치 필요                                                          |
| Linux   | 서비스 패키지 설치                             | 표준 Wayland 빌드는 로그인된 세션을 캡처. [무인 접속 프리뷰](/ko/blog/unattended-remote-access-wayland-ko)는 로그인 화면 접속 추가(x86_64 Debian/Ubuntu) |
| Android | 영구 비밀번호 설정, 캡처 활성화                | 화면이 켜져 있어야 하며, 화면 캡처(MediaProjection) 동의와 입력 권한을 부여해야 함                                                                |

### Windows

가장 간단합니다. 설치하고, 서비스를 켜고, 영구 비밀번호를 설정하면 끝입니다. 서비스가 부팅 시 실행되므로 로그인 화면 무인 접속과 재부팅 후 접속이 예상대로 작동합니다.

### macOS

macOS는 화면 캡처와 입력을 권한으로 제한합니다. 설치 후 **시스템 설정 → 개인정보 보호 및 보안**을 열어 RustDesk에 **화면 기록**과 **손쉬운 사용** 권한을 모두 부여하세요. 사용자가 로그인하기 전인 _로그인 창_ 에서 접속하려면 RustDesk 서비스/헬퍼가 설치되어 있어야 로그인 전 화면을 캡처할 수 있습니다. 그렇지 않으면 검은 화면만 나오며, 이는 [검은 화면 가이드에서 다루는 캡처 문제](/ko/blog/rustdesk-connected-waiting-for-image-ko)와 같은 현상입니다.

### Linux

서비스가 부팅 시 실행되도록 RustDesk를 설치하세요. 표준 RustDesk 빌드는 로그인된 세션에서 PipeWire와 `xdg-desktop-portal`을 통해 Wayland 데스크톱을 캡처하며, 1.4.3부터는 다중 모니터도 지원합니다. 로그인 화면(그리터)에 머물러 있는 컴퓨터라면 **x86_64 Debian/Ubuntu 계열 시스템**용 별도 [Wayland 무인 접속 프리뷰](/ko/blog/unattended-remote-access-wayland-ko)가 무인 접속과 재부팅 후 로그인 화면 접속을 추가합니다. 배포판이 아직 X11 로그인 그리터를 제공한다면 그것도 한 방법이며, 헤드리스 기기에는 더미 플러그나 가상 디스플레이를 추가하세요. 자세한 내용은 [리눅스용 RustDesk](/ko/blog/rustdesk-for-linux-ko)를 참고하세요.

## 3단계: 사전 구성된 클라이언트로 대규모 배포

컴퓨터 한 대는 직접 설정해도 괜찮지만, 50대는 그렇지 않습니다. **Basic 이상의 자체 호스팅 플랜**에서는 웹 콘솔의 **커스텀 클라이언트 생성기**가 **서버 주소, 공개 키, 설정이 미리 반영된** 설치 파일을 만들어 주므로 최종 사용자가 아무것도 입력할 필요가 없습니다. 기존 배포 도구(그룹 정책, Intune, MSP용 RMM, 셸 스크립트)와 함께 쓰면 각 기기가 처음 실행될 때 서비스를 설치하고 _자체_ 서버에 등록됩니다.

바로 이 부분에서 자체 호스팅이 팀에 효과를 발휘합니다. 모든 기기가 직접 운영하는 ID/랑데부 서버와 릴레이 서버에 등록됩니다([MSP를 위한 RustDesk](/ko/blog/rustdesk-for-msps-ko) 참고). Server Pro 플랜은 **로그인 사용자와 관리 대상 기기**를 기준으로 라이선스가 산정됩니다. 표준 플랜에는 무제한 동시 연결이 포함되며, [Customized V2](https://rustdesk.com/pricing#custom2)만 정해진 수의 동시 연결을 라이선스로 제공합니다. 예산은 보유한 컴퓨터와 관리자 수를 기준으로 세우세요. [관리 대상 기기로 계산되는 기준](/ko/blog/what-counts-as-a-managed-device-ko)도 참고하세요. 웹 콘솔은 리버스 프록시 뒤에서 [HTTPS로 제공](https://rustdesk.com/docs/ko/self-host/rustdesk-server-pro/faq/#웹-콘솔용-https-수동-설정)하세요.

## 보안 강화하기

무인 접속은 컴퓨터로 들어가는 상시 열린 문과 같으므로 자격 증명을 신중하게 다뤄야 합니다.

- **강력하고 고유한 영구 비밀번호**를 쓰고 주기적으로 교체하세요.
- 피제어 기기에서 **연결 2FA**를 켜고, Server Pro에서는 [접근 제어](https://rustdesk.com/docs/ko/self-host/rustdesk-server-pro/permissions/)를 사용하세요. 접근 제어는 사용자 및 기기 그룹 규칙으로 누가 어떤 기기에 접속할 수 있는지 결정합니다(사용자 그룹과 기기 그룹 권한은 누적됩니다). 공유 주소록은 항목을 정리할 뿐 접근 경계가 아닙니다. [제어 역할](https://rustdesk.com/docs/ko/self-host/rustdesk-server-pro/control-role/)은 기술자가 세션 안에서 할 수 있는 작업을 제한합니다.
- **서버를 자체 호스팅**해 랑데부, 릴레이, 콘솔, 저장된 관리 데이터를 직접 고른 인프라에서 운영하세요. RustDesk 클라이언트와 Server OSS(무료 커뮤니티 서버)는 AGPL 라이선스이므로 인증 코드를 검토할 수 있으며, Server Pro는 상용 독점 자체 호스팅 서버 소프트웨어입니다.

## 직접 통제하는 무인 접속

항상 켜져 있는 기기들을 직접 운영하는 서버에 연결하면, 이 기기들에 대한 상시 접속은 빌려 쓰는 클라우드가 아니라 직접 소유한 하드웨어를 통해 중개됩니다. 상시 접속이라면, 그 경로를 직접 쥐고 있는 것은 짧은 설정 시간을 들일 만한 가치가 있습니다.
