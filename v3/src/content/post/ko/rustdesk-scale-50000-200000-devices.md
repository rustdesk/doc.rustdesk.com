RustDesk 내부 텔레메트리는 2026년 7월 7일, **12코어 CPU와 32GB RAM**을 갖춘 공개 서버 호스트 한 대에서 **200만 대가 넘는 온라인 엔드포인트**를 기록했습니다.

이 수치의 범위를 정하는 단서가 두 가지 있습니다. 첫째, "온라인 엔드포인트"는 그 시점에 온라인으로 보고된 기기를 뜻하며, 200만 건의 동시 원격 제어 세션이 아닙니다. 둘째, 이는 내부 프로덕션 관측일 뿐 독립적으로 감사된 벤치마크나 Server Pro 보장 수치가 아닙니다. Server Pro 배포에는 데이터베이스 쓰기, 감사 활동, 콘솔 사용, 정책 처리, 릴레이 트래픽이 더해집니다.

## 짧은 답변

**온라인 기기 20만 대는 Server Pro에서 현실적인 계획 목표입니다.** 위의 공개 서버 관측치는 12코어, 32GB 호스트 한 대에서 그보다 한 자릿수 더 큰 규모입니다. 파일럿에서 검증할 것은 엔드포인트 접속 위에 Server Pro가 더하는 부하, 즉 기기 상태 변화, 정책, 감사 쓰기, 콘솔 사용, 동시 릴레이 세션입니다.

## 자세히 살펴보면

확장성은 TeamViewer나 AnyDesk에서 옮겨 오는 IT 팀, 특히 수만에서 수십만 대 규모의 기기를 계획하는 팀에게서 저희가 가장 자주 받는 질문 중 하나입니다. 답은 얼마나 많은 기기가 온라인 상태를 유지하는지, 상태가 얼마나 자주 바뀌는지, 동시에 진행되는 원격 세션이 몇 개인지, 릴레이를 거치는 트래픽이 얼마나 되는지에 따라 달라집니다.

Server Pro를 배포할 때는 공개 서버 수치가 다루지 않는 부분을 검증하세요. 기기가 온라인과 오프라인을 오가면 캐싱과 데이터베이스 쓰기 성능이 중요해집니다. 릴레이 대역폭과 CPU 사용량은 동시에 릴레이되는 세션의 수, 지속 시간, 해상도, 코덱에 따라 달라집니다. 콘솔 조회, 감사 로그 보존, 기기 그룹, 정책, 외부 연동도 엔드포인트 접속 수만으로는 측정되지 않는 부하를 더합니다. 목표 온라인 기기 수, 연결 상태 변화, 동시 직접·릴레이 세션 수, 데이터베이스 보존 기간, 관리 활동을 실제 환경을 대표하는 부하 테스트에 반영하세요.

반복 가능한 Server Pro 파일럿을 위해 클라이언트/서버 버전, 하드웨어, 데이터베이스와 릴레이 배치를 기록하세요. 예상되는 콘솔 조회, 정책 업데이트, 감사 쓰기를 실행하면서 온라인 기기 수와 상태 변화를 단계적으로 늘리세요. 등록/재연결 성공률, 연결 설정 시간, 데이터베이스 지연, CPU/RAM, 디스크 증가량, 릴레이 처리량을 측정하세요. 최대 동시 세션과 복구 훈련도 포함하고, 이 측정값은 온라인 엔드포인트 수와 구분해 두세요.

고가용성과 로드 밸런싱도 같은 방식으로 다뤄야 합니다. 릴레이는 수평 확장이 가능합니다. 여러 대를 운영하고 지역별로 배치할 수 있으며, hbbr 릴레이에는 라이선스가 필요 없습니다. Pro 라이선스는 hbbs 서버 한 대에 바인딩되므로 ID 서버와 데이터베이스의 장애 조치는 명시적으로 설계하고, 매우 큰 규모라면 RustDesk와 함께 검토하세요.

그다음 라이선스 규모를 정하세요. Server Pro는 로그인 사용자와 관리 대상 기기를 기준으로 라이선스가 산정되며, 표준 요금제에는 무제한 동시 연결이 포함됩니다. 기기 규모에 맞는 등급은 [rustdesk.com/pricing](https://rustdesk.com/pricing)에서 고르세요.
