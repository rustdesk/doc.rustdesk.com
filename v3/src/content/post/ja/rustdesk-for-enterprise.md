## リモートアクセスを自社管理下のインフラに置く

RustDesk Server Proは、ID/ランデブー、リレー、Webコンソール、デバイスデータを自社の境界内で稼働させ、BasicプランからLDAP/ADとOIDC SSOを、標準プランでは無制限の同時接続を提供します。インフラの管理権限、ID管理、アクセスポリシー、監査可能性、スケール、ライセンスの見通しという、企業の評価で通常焦点になる点をカバーしています。

RustDeskのクライアントとRustDesk Server OSS（無料のコミュニティサーバー）はAGPLライセンスで、Server Proは商用のプロプライエタリなセルフホスト型サーバーソフトウェアです。

## 根本的な違い：自分でホストするから、自分で管理できる

RustDesk Server Proは**セルフホスト型**で、サーバーを運用するのはベンダーではなく自社のチームです（[チームがセルフホストを選ぶ理由](/ja/blog/why-self-host-remote-desktop-software-ja)）。このアーキテクチャ上の一点が以下のメリットの大半を生み、<strong>[AGPLライセンスのクライアント](https://github.com/rustdesk/rustdesk)</strong>を単なる宣伝文句以上のものにしています。本番環境のエンドポイントに入れるエージェントすべてに説明責任を負うセキュリティチームは、ソースコードを読み、クライアントを自分たちでビルドできます。「実際に動くものを正確に監査できる」が、本当に満たせる調達要件になるのです。

## 最初に答えるべきエンタープライズアーキテクチャの問い

機能表を比べる前に、導入設計を明確にしておきます。

| 決定事項           | 設計で明記すべきこと                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| ID管理             | OIDCまたはLDAPのソース、MFAポリシー、緊急時アクセス（break-glass）、アカウントのライフサイクル                             |
| 認可               | デバイスグループの所有者、技術者のロール、委託先の権限範囲、承認モデル                                                     |
| ネットワーク       | IDサーバーとリレーの配置、直接接続とリレー接続の方針、公開するポート、地域ごとのルーティング                               |
| 可用性             | キャパシティの前提、監視、バックアップ、復旧目標、複数リレーの設計                                                         |
| エンドポイント管理 | サポート対象のOSバージョン、クライアントのパッケージング、設定の強制、アップデートのSLA                                    |
| セキュリティ運用   | ログ記録、保持期間、アラート、脆弱性への対応、インシデント対応の責任者                                                     |
| ライセンス         | 必要なログインユーザー数、管理対象デバイス数、[Customized V2](https://rustdesk.com/pricing#custom2)を使う場合の同時接続数 |

RustDeskはリモートアクセスのコンポーネントとエンタープライズ向けの制御機能を提供します。それが組織の可用性、コンプライアンス、運用の要件を満たすかどうかは、自社のアーキテクチャで決まります。

## データ管理とコンプライアンス

セルフホストすれば、ランデブー、リレー、コンソール、保存されるデバイスデータをどこに置き、誰が運用するかを選べます。ただし直接セッションはエンドポイント間を流れるため、サーバーの所在地だけでは、通信が国内にとどまることもGDPRへの準拠も保証されません。[データフローとコンプライアンス上の管理策](/ja/blog/remote-desktop-data-sovereignty-gdpr-ja)の全体を文書化してください。

Server Proは、接続、ファイル転送、アラーム、コンソール操作の[監査ログ](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/audit-logs/)を記録します。<strong>設定 > その他 > ログ保存期間（日）</strong>に正の数を設定すると、それより古いログが自動で削除され（クリーンアップは1時間ごと）、`0`ではログを無期限に保持します。消去の要請には、コンソールやAPIからユーザーとデバイスを無効化または削除して対応できます。外部への通信として計画に含めるべきなのは、Proのライセンス検証、カスタムクライアントのビルドサービス、クライアントのアップデート、接続する外部IDプロバイダーです。

これは、コストを理由にした移行が起きる隠れた理由でもあります。多くの企業チームは価格そのものだけでなく、使い切れていないクラウドサービスと機能のセットに対価を払っていることにも不満を感じています。セルフホストはこの構図を逆にします。必要なものだけを用意すればよく、他社のデータセンターを必須の仲介役として借りる必要はありません。

## スケールと同時接続のライセンス

エンタープライズの導入がつまずく軸は、技術的な上限と価格の上限の2つです。RustDeskはその両方に応えます。

技術面では、2026年7月7日、RustDeskのパブリックサーバーが12コア・32GBのホスト1台で200万を超えるオンラインのエンドポイントを記録しました（社内テレメトリによる値で、監査済みのベンチマークでもServer Proの性能保証でもありません）。Server Proについては、[20万台規模の計画ガイド](/ja/blog/rustdesk-scale-50000-200000-devices-ja)で、パイロットで検証すべきデータベース、コンソール、リレーの負荷を解説しています。

RustDeskは**ログインユーザー数と管理対象デバイス数**で課金します。標準プランには無制限の同時接続が含まれ、同時接続数をライセンスで定めるのは[Customized V2](https://rustdesk.com/pricing#custom2)だけです。[サブスクリプションの途中でのアップグレード](/ja/blog/upgrade-rustdesk-license-mid-subscription-ja)はいつでも可能で、有効期限はアップグレード日から丸1年に延長され、現在のライセンスで支払い済みの残存分が充当されます。

## 管理者が期待するAD/LDAPとアクセス制御

企業のリモートアクセスは、「誰がどのマシンに接続できるのか、それを証明できるのか」という問いに答えなければなりません。RustDeskの有料プランには<strong>Basicプラン以上で利用できるLDAP/SSO（OIDC）</strong>が含まれているため、別のユーザーリストを維持せずに、すでに運用しているIDソースに基づいて技術者のアクセス権を付与できます。

[アクセス制御](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/permissions/)は、ユーザーの割り当て、デバイスグループ、グループ間のルールによって、誰がどのデバイスに接続できるかを決めます。各デバイスは1つのデバイスグループに所属し、ユーザーグループとデバイスグループの権限は累積されます。共有アドレス帳は技術者向けにデバイスのエントリを整理するもので、アクセスの境界ではありません。[コントロールロール](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/control-role/)は、技術者がセッション中にできる操作を制限します。カスタムクライアントジェネレーターもBasicプランから利用できます（[プランの比較表](https://rustdesk.com/pricing)を参照）。

## 一括展開と自動化

数千台のエンドポイントにリモートアクセスを手作業で展開するのは現実的ではないため、RustDeskは標準的なエンタープライズ向けの展開方法に対応しています。Windows向けには**MSIパッケージ**があり、`msiexec /qn`でサイレントな無人インストールができます。**グループポリシー（GPO）、Microsoft Intune、RMM、任意のパッケージングツール**で配信でき、インストール先、ショートカット、各種オプションを指定するコマンドラインパラメーターも用意されています。これを[カスタムクライアントジェネレーター](https://rustdesk.com/docs/ja/self-host/client-configuration/)と組み合わせれば、展開するクライアントは最初から自社のサーバーと設定に合わせて構成されており、マシンごとの設定は不要です。

フリートの運用には、[Windows MSIのリファレンス](https://rustdesk.com/docs/ja/client/windows/msi/)、[クライアント展開ガイド](https://rustdesk.com/docs/ja/self-host/client-deployment/)、[Server ProのAPI・CLIツール](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/console/)を使ってください。管理ツールは、ユーザー、デバイス、グループ、アドレス帳、ストラテジー、監査を扱えます。APIトークンの権限は作業に必要な範囲に絞り、登録、無効化、削除の流れをパイロットで検証してください。

## 本番展開前の受け入れ確認

本番展開の前に、想定しているユーザーとデバイスのアクセスマトリクス、IDの復旧手順、無人アクセス、クライアントのアップデート、ピーク時のリレー容量、ログの保持、バックアップからの復元を検証してください。こうした受け入れ確認を経て、セルフホストによるインフラの管理権限が、運用できるエンタープライズの導入になります。

## エンタープライズの管理を、自社の条件で

エンタープライズの規模では、論点は明快です。ID/リレー、コンソール、保存データは自社の境界内にあり、自社のIDシステムとアクセスポリシーにつながっていて、中核部分をベンダーが運用することはありません。調達部門やセキュリティチームが求めるのはこの体制であり、RustDesk Server Proはそれを実現するために作られています。

## 導入を決める前に試す

<strong>[営業との商談なしに](https://www.youtube.com/@rustdesk)</strong>評価を進められます。方法は2つです。

- **Server OSSでアーキテクチャを検証する。** ライセンス料も有効期限もなく無料で、自社のネットワークで動くため、セキュリティチームにセルフホストのモデルを低リスクで示せます。
- **ID管理、アクセス制御、クライアント生成といったProの機能については、**[rustdesk.com/pricing](https://rustdesk.com/pricing)で現行のプランを確認したうえで、[sales@rustdesk.com](mailto:sales@rustdesk.com)に自組織で利用できる評価条件をお問い合わせください。

いずれの場合も、自社の環境にサーバーを立てて検証してから、導入を決めてください。
