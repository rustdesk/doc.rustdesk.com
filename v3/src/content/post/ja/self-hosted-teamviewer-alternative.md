**セルフホスト型のTeamViewerやAnyDeskの代替**を探し始めるきっかけは、たいてい同じです。更新の見積もりが実際に使っているワークフローに見合わなくなり、しかも製品は相変わらず、自社で管理していないインフラを通してセッションを仲介している。RustDeskはその両方に代わるセルフホスト型の選択肢です。ID/ランデブーサーバーとリレーサーバーを自社で運用し、まずはRustDesk Server OSS（無料のコミュニティサーバー）から始めて、集中管理が必要になったら商用のServer Proを追加できます。

## TeamViewerやAnyDeskを離れる理由

意思決定を左右する要因として、繰り返し挙がるのは次の2つです。

**コスト。** 更新時の総額は、実際の利用状況とは関係なく膨らむことがあります。プラン体系、アドオン、料金改定のいずれもが金額を動かします。現在の見積もりを、同じ要件のもとで代替製品と比較してください。

**コントロール。** ベンダーがホストするサービスでは、一般に接続の調整と管理データをベンダーが運用し、セッションのメディアは直接またはリレー経由で流れます。TeamViewerの標準サービスはこのモデルで、AnyDeskにはUltimate On-Premisesアプライアンスもあります。

RustDeskの**クライアントとServer OSSはAGPLライセンス**で、誰でも独自に検査し、ビルドできます。Server OSSは、ID/ランデブーサービスとリレーサービスをライセンス料も有効期限もなく提供します。**Server Proは商用のプロプライエタリなセルフホスト型サーバーソフトウェア**で、自社のインフラ上に集中管理機能を追加します。どちらを選んでも、サーバーをどこで稼働させ、誰が運用するかは自社で決められます。

ただし注意点が一つあります。直接セッションはエンドポイント間を流れ（リレー経由のセッションは自社のリレーを使います）、セルフホストはデプロイメント上の管理手段であって、コンプライアンス認証ではありません。通信を国内にとどめられるかどうかやGDPR上の義務は、引き続きデプロイメントのルーティングと運用方法に左右されます。

## ログインユーザー数、デバイス数、プランごとの同時接続数で決まるライセンス

RustDeskは、ログインユーザー数と管理対象デバイス数でライセンスされます。**標準プラン（Individual、Basic、Customized）には無制限の同時接続が含まれ、同時接続数をライセンスで定めるのはCustomized V2だけです。** この同時接続数は操作中の制御側デバイスの数で数えるため、1台の技術者端末で5つのセッションタブを開いていても1接続です。[アップグレード](/ja/blog/upgrade-rustdesk-license-mid-subscription-ja)はセルフサービスポータルでいつでも購入でき、有効期限はアップグレード日から丸1年に延長され、現在のライセンスで支払い済みの残存分が充当されます。3つの数値すべてを最新の料金ページに当てはめて試算してください。

この体系は、サポートチームの成長の仕方にそのまま合います。非常に大規模な環境向けには、RustDeskが[大規模フリートの計画](/ja/blog/rustdesk-scale-50000-200000-devices-ja)ガイダンスを公開しています。20万台のオンラインデバイスを計画上の目標とし、自社のキャッシュ、データベース、リレーのワークロードで検証する内容です。

## MSPやITチームのために設計

Server Proは、セルフホスト型のコンソール、デバイスグループ、共有アドレス帳、ユーザー単位・デバイスグループ単位の[アクセス制御](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/permissions/)、セッション中の操作に対する[コントロールロール](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/control-role/)の権限を提供し、カスタムクライアントジェネレーターと[LDAP/OIDC SSO](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/ldap/)はBasicプランから利用できます。各デバイスは1つのデバイスグループに所属し、ユーザーグループとデバイスグループのアクセス権限は累積されます。

## TeamViewerからの移行で考慮すべきこと

TeamViewerの運用環境には、単純な一対一のチェックリストでは見落としがちな機能が積み重なっています。プランを選ぶ前に次の点を洗い出してください。また、条件も機能の提供状況も時間とともに変わるため、最新の情報は各ベンダーに確認してください。

- **プラン固有の機能。** **TeamViewer Tensor**のようなエンタープライズ向けプランには、条件付きアクセス、一括展開、SSO／ディレクトリのプロビジョニングといった制御が加わっており、一対一で対応するとは限りません。実際に依存している機能を書き出してください。**TeamViewer Frontline**（AR・現場作業者向けスイート）を使っている場合は、リモートデスクトップの移行とは切り離した別製品として扱ってください。
- **条件付きアクセスとデバイスポリシー。** TeamViewerのルールベースのアクセス制御や配布したポリシー設定で、誰がどのマシンに接続できるかを制限している場合は、それらのルールをRustDeskのデバイスグループ、共有アドレス帳、最小権限のアクセスルールにどう置き換えるかを計画してください。
- **管理コンソールとグループ構造。** TeamViewerは、デバイス、共有グループ、ユーザーや会社のプロファイルを管理コンソールで整理しています。その階層を棚卸しし、同等のグループ分けと所有関係をセルフホスト型のコンソールで再構築できるようにしてください。
- **デバイス単位とシート単位の数え方の違い。** TeamViewerとRustDeskではライセンスの数え方が異なります。シート数がそのまま引き継がれると考えず、実際の利用状況（ライセンスユーザー数、管理対象デバイス数、同時セッション数）を、ログインユーザー数と管理対象デバイス数に基づくRustDeskのモデルに当てはめて試算し直してください。
- **確認すべき機能の同等性。** リモート印刷、セッション録画、モバイル対応、Wake-on-LAN、特定の連携機能がTeamViewerのワークフローで必須なら、同等の機能があると決めつけず、パイロット運用中にRustDeskで一つずつ確認してください。

## AnyDeskからの移行で特に変わる点

TeamViewerではなくAnyDeskから移行する場合に特有の点がいくつかあります。

- **商用利用の検出機能がない。** AnyDeskの無料プランは、[商用利用](/ja/blog/anydesk-commercial-use-detected-ja)と判断したアカウントにフラグを立てることがあります。RustDesk Server OSSにはそのような商用利用の判定機能はなく、Server Proでは購入したライセンスの上限が適用されます。
- **標準プランにはティアごとの同時接続の上限がない。** RustDeskのProの標準プランには無制限の同時接続が含まれ、同時接続数をライセンスで定めるのはCustomized V2だけです。AnyDeskの同時接続の枠はプランによって異なります。コストの試算にはログインユーザー数とデバイス数を含め、容量を追加する前に[アップグレード時の計算方法](/ja/blog/upgrade-rustdesk-license-mid-subscription-ja)を確認してください。
- **再作成が必要なアドレス帳、エイリアス、無人アクセス。** 依存しているAnyDeskのエイリアス、アドレス帳のエントリ、無人アクセス用のパスワードを棚卸しし、RustDeskのログインユーザー、デバイスグループ、共有アドレス帳に対応付けてください。
- **カスタム名前空間やブランド化したクライアント。** カスタム名前空間やブランド化したクライアントでAnyDeskを運用している場合は、エンドユーザーが同じ見た目のツールを使い続けられるよう、同等のカスタムブランドのRustDeskクライアントを用意する計画を立ててください。

## 移行計画

これらの機能を棚卸ししたら、段階的に移行します。

1. 非本番環境にRustDeskを構築し、直接接続とリレー経由の両方の経路をテストする。
2. ユーザー、グループ、アドレス帳の所有関係を、最小権限に基づくRustDeskのアクセスルールに対応付ける。
3. Windows、macOS、Linux、モバイルの代表的なデバイスでパイロット運用を行い、権限昇格と無人アクセスも含めて検証する。
4. 更新、鍵のバックアップ、証明書の更新、ログ記録、監視、災害復旧を検証する。
5. 対象を決めたグループで現行ツールとRustDeskを並行運用し、ロールバック手順を文書化しておく。
6. 新しいサービスが受け入れ基準を満たし、サポートスタッフのトレーニングが終わってから、旧エージェントを削除する。

この手順を踏めば、ライセンスに関する判断が、検証されていないインフラの切り替えにすり替わる事態を防げます。

## 自社インフラで乗り換えを検証する

始めるのに誰かと話す必要はありません。Server OSSは自社のハードウェアにインストールでき、ライセンス料も有効期限もなく無料で使えます。上記の移行計画に沿ってProの機能を試したい場合は、[sales@rustdesk.com](mailto:sales@rustdesk.com)に現在の評価条件をお問い合わせください。標準プランの料金は[rustdesk.com/pricing](https://rustdesk.com/pricing)に掲載しています。まず動作を見てみたい場合は、[デモ動画](https://www.youtube.com/@rustdesk)でセッションの最初から最後までをご覧いただけます。

セルフホストがコストとコントロールの両面で期待に応えるかどうかを見極める最も早い方法は、自社のハードウェアで短期間の概念実証（PoC）を行うことです。
