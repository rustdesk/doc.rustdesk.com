無人アクセスとは、誰も前に座っていないコンピューターに接続することです。ラックに収まったサーバー、キオスク端末、遠く離れた家族のPCなどが対象になります。RustDeskでは、次の2つがそろえば無人アクセスがうまく機能します。接続のたびに誰かが承認しなくて済む**固定パスワード**と、ログイン前やログアウト後でも使えるようにする**サービスとしての実行**です。このガイドでは、この2つに加えて、プラットフォームごとの権限と、フリート全体への展開方法を説明します。

## 結論から言うと

**固定パスワード**を設定し（設定 → セキュリティ）、マシンとともに起動する**システムサービスとしてRustDeskをインストール**します。既定の承認モードは固定パスワードをそのまま受け付けるので、誰かが承認をクリックする必要はありません。サービスはログイン中のユーザーとは無関係に動くため、Windowsのログイン画面も含めて、いつでも接続できます。macOSでは画面収録とアクセシビリティの権限も必要です。大規模に展開するには、事前設定済みのクライアントを生成し、各マシンが自社のサーバーに対して自動でインストールされるようにします。

## ステップ1：固定パスワードを設定する

RustDeskは既定で、定期的に変わるワンタイムパスワードを表示し、リモート側にいる人がそれを読み上げて伝える仕組みになっています。無人アクセスでは、これを固定の認証情報に置き換えます。

1. 接続したいマシンでRustDeskを開きます。
2. **設定 → セキュリティ**に移動します（古いビルドでは、メイン画面のパスワード欄です）。
3. **固定パスワードを設定**を選び、推測されにくく使い回していない値を入力します。

既定の設定のままで、このパスワードは受け付けられます。セッションはパスワードとクリックの両方の方法で承認でき、両方の種類のパスワードが許可されているからです。誰かが承認モードをクリックのみに、またはパスワードの種類をワンタイムのみに変更していた場合は、**パスワードでセッションを承認**（または**両方の方法でセッションを承認**）と、**固定パスワードを使用する**（または**両方のパスワードを使用する**）に戻してください。管理された環境に展開する場合、対応する[設定キー](https://rustdesk.com/docs/ja/self-host/client-configuration/advanced-settings/#approve-mode)は`approve-mode`（既定値は`password-click`）と`verification-method`（既定値は`use-both-passwords`）です。

[RustDeskクライアントのドキュメント](https://rustdesk.com/docs/ja/client/)でも、これが無人アクセスの中心であると説明されています。特に強調したいルールが一つあります。**OSのログインパスワードを使い回さないでください。** RustDesk専用の十分に複雑なパスワードを使えば、一方の認証情報が漏れても、もう一方まで危険にさらされることはありません。

## ステップ2：サービスとしてインストールし、起動時に開始させる

多くの人が見落とすのがこのステップです。ポータブル版の`.exe`や`.app`はユーザーのセッションの中で動くため、ユーザーがログアウトすると止まります。また、Windowsでは権限を昇格しないとUACのセキュアデスクトップを操作できません（有人サポート向けには[ポータブル版の権限昇格](https://rustdesk.com/docs/ja/client/windows/windows-portable-elevation/)があります）。本当の意味で無人にするには、RustDeskをバックグラウンドの**システムサービス**として動かす必要があります。

- ポータブル版ではなく、RustDeskの**インストーラー**を実行してインストールを完了します。
- **設定 → 一般**で**サービス**が動作していることを確認し、停止している場合は**開始**を押します。インストール後は、マシンの起動時にサービスが自動で開始されます。

RustDeskがサービスとして動くようになると、誰かがログインする前に読み込まれます。これにより、**ログイン画面**に接続してリモートで認証し、誰もいなくても再起動して再接続することまでできるようになります。macOSとLinuxには、画面キャプチャと表示セッションに関する独自の要件があり、以下で説明します。

## プラットフォーム別の注意点

| プラットフォーム | 実施内容                                               | 注意点                                                                                                                                                           |
| ---------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows          | インストールし、サービスを動作させておく（起動時に開始） | ポータブル版はログアウトで止まり、権限を昇格しないとUACのプロンプトを操作できない。インストーラーを使う                                                          |
| macOS            | インストールし、固定パスワードを設定し、権限を付与する | 画面収録とアクセシビリティの付与が必須。ログイン画面のキャプチャにはヘルパーのインストールが必要                                                                 |
| Linux            | サービスのパッケージをインストールする                 | 標準のWayland対応ビルドはログイン中のセッションをキャプチャする。[無人アクセスのプレビュー版](/ja/blog/unattended-remote-access-wayland-ja)はログイン画面へのアクセスを追加（x86_64のDebian/Ubuntu系） |
| Android          | 固定パスワードを設定し、キャプチャを有効にする         | 画面が起きていること。画面キャプチャ（MediaProjection）の同意と入力の権限が必要                                                                                  |

### Windows

最もシンプルです。インストールしてサービスを有効にし、固定パスワードを設定すれば完了です。サービスは起動時に動き出すため、ログイン画面への無人アクセスも、再起動をまたいだアクセスも想定どおりに機能します。

### macOS

macOSでは、画面キャプチャと入力操作が権限で制御されています。インストール後に**システム設定 → プライバシーとセキュリティ**を開き、RustDeskに**画面収録**と**アクセシビリティ**の両方を許可してください。誰もログインしていない*ログインウィンドウ*でアクセスするには、ログイン前の画面をキャプチャできるようRustDeskのサービス／ヘルパーをインストールしておく必要があります。そうしないとそこで黒い画面になります。[黒い画面の対処ガイドで扱っているキャプチャの問題](/ja/blog/rustdesk-connected-waiting-for-image-ja)と同じものです。

### Linux

RustDeskをインストールし、サービスが起動時に動くようにします。標準のRustDeskビルドは、ログイン中のセッションでPipeWireと`xdg-desktop-portal`を通じてWaylandのデスクトップをキャプチャし、1.4.3以降は複数のモニターにも対応しています。ログイン画面（グリーター）のまま待機しているマシン向けには、**x86_64のDebian/Ubuntu系システム**を対象とした別の[Wayland無人アクセスのプレビュー版](/ja/blog/unattended-remote-access-wayland-ja)があり、無人アクセスと再起動後のログイン画面へのアクセスが加わります。ディストリビューションがX11のログイン画面を提供している場合はそれも選択肢で、ヘッドレスのマシンにはダミープラグか仮想ディスプレイを追加してください。詳しくは[RustDesk for Linux](/ja/blog/rustdesk-for-linux-ja)をご覧ください。

## ステップ3：事前設定済みのクライアントで大規模に展開する

1台を手作業で設定するのは問題ありませんが、50台となると話は別です。**Basic以上のセルフホスト型プラン**では、Webコンソールの**カスタムクライアントジェネレーター**で、**サーバーアドレス、公開鍵、各種設定をあらかじめ組み込んだ**インストーラーを作成できるため、エンドユーザーは何も入力しません。既存の展開ツール（グループポリシー、Intune、MSPのRMM、シェルスクリプトなど）と組み合わせれば、各デバイスは初回起動時にサービスをインストールし、*自社の*サーバーに登録されます。

チームにとってセルフホストの効果が出るのはここです。フリート全体が、自社で運用するID/ランデブーサーバーとリレーサーバーに登録されます（[MSP向けRustDesk](/ja/blog/rustdesk-for-msps-ja)を参照）。Server Proのプランは**ログインユーザー数と管理対象デバイス数**でライセンスされます。標準プランには無制限の同時接続が含まれ、同時接続数をライセンスで定めるのは[Customized V2](https://rustdesk.com/pricing#custom2)だけです。予算はマシンの台数と管理者の人数で見積もってください（[何が管理対象デバイスとしてカウントされるか](/ja/blog/what-counts-as-a-managed-device-ja)を参照）。Webコンソールはリバースプロキシの背後で[HTTPSで提供](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/faq/)してください。

## しっかりと保護する

無人アクセスはマシンへの常設の扉です。認証情報は真剣に扱ってください。

- **強力で使い回しのない固定パスワード**を使い、定期的に変更する。
- 被制御デバイスで**接続時の2FA**を有効にし、Server Proでは[アクセス制御](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/permissions/)を使う。アクセス制御は、ユーザーとデバイスグループのルールで誰がどのデバイスに接続できるかを決めます（ユーザーグループとデバイスグループの権限は累積されます）。共有アドレス帳はエントリを整理するだけで、アクセスの境界にはなりません。[コントロールロール](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/control-role/)は、技術者がセッション中にできる操作を制限します。
- **サーバーをセルフホストする。** ランデブー、リレー、コンソール、保存される管理データを、自社で選んだインフラで運用できます。RustDeskのクライアントとServer OSSはAGPLライセンスなので、認証のコードを検証できます。Server Proは商用のプロプライエタリなセルフホスト型サーバーソフトウェアです。

## 自分で管理する無人アクセス

常時稼働のフリートを自社で運用するサーバーに向ければ、それらのマシンへの常設アクセスは、借りているクラウドではなく自社のハードウェアが仲介し続けます。恒久的なアクセスだからこそ、その経路を自分の手で握っておく価値は、短いセットアップの手間を十分に上回ります。
