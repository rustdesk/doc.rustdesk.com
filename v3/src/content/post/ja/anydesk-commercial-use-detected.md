自宅のPCに接続しようとしたり、家族を手伝おうとしたりしてAnyDeskを開いたら、**商用利用が検出された**、あるいは業務での利用にはライセンスが必要だという警告が出た――そんな状況ではないでしょうか。AnyDeskの[利用規約](https://anydesk.com/en/terms)は、無料版を個人の非商用利用に限定し、その境界を運用で守ることを認めています。分類が誤っている場合は、まず公式の審査を利用してください。実際に商用利用に当たる場合は、規約をすり抜けようとせず、有料やセルフホスト型の選択肢を比較してください。

## AnyDeskアカウントの「商用利用が検出されました」を解決する方法

AnyDeskは、本当に個人の非商用利用であるユーザー向けに、公式の[ホワイトリスト申請](https://anydesk.com/en/commercial-use)を用意しています。大まかな流れは次のとおりです。

1. **AnyDeskアドレス（ID）を控える。** クライアントを開くと表示される番号で、接続*元*と接続*先*を含む、関係するすべてのデバイスの分が必要です。
2. **AnyDeskの公式の[商用利用／ホワイトリスト申請フォーム](https://anydesk.com/en/commercial-use)を開く。**
3. **実際の利用状況を正直に書く。** たとえば「両親の自宅のPCを手伝うためだけに使っています」など、実際にしていることをそのまま説明します。
4. **送信して、AnyDeskの審査を待つ。** 問い合わせが必要な場合は、現在のフォームに記載された連絡先を使ってください。

結果は2通りです。AnyDeskが個人利用だと確認してホワイトリストに登録するか、商用利用と判断してフラグがそのまま残るかです。申請が役に立つのは、フラグが本当に誤検知だった場合だけです。実際に商用利用であれば、審査の結果も回避策もその事実を変えません。また、ネットで出回っている「設定ファイルを削除する」といった非公式のリセット手法は紹介しません。AnyDeskのライセンス条件をすり抜けるだけで、利用が本当に商用に当たるかどうかという問題は何も解決しないからです。

### ここで言う「商用利用」とは

AnyDesk自身の規約では、**個人利用**とは業務ではない利用、つまり自分のデバイスへのアクセスや友人・家族の手助けで、直接的にも間接的にも報酬が発生しないものです。一方、ホワイトリスト申請で認められない、また認められるべきでもない**商用（業務）利用**には、次のものが含まれます。

- 顧客、取引先、同僚へのサポート
- 業務用のマシンへの接続や仕事のメールの確認を含む、あらゆるリモートワーク
- 商取引、事業、職業の一環として行うあらゆる接続
- 組織のためのサーバー管理や複数デバイスの管理
- 直接的または間接的に報酬を得ているあらゆる利用

どれかに当てはまるなら、AnyDeskのフラグは正しく、長く使える解決策は実際の働き方に合ったライセンスのツールを使うことです。それについては以降で説明します。

## AnyDeskが「商用利用」にフラグを立てる理由

AnyDeskは公式の検出しきい値を公開していないため、サードパーティの投稿に出てくる具体的な接続回数、セッション時間、デバイス数の上限、タイムアウトは、頼れるルールではなく未検証の情報として扱ってください。同じライセンス上の区別は、[TeamViewerの商用利用の判定](/ja/blog/teamviewer-commercial-use-detected-ja)をはじめ、ほかのリモートアクセス製品にもあります。本当に商用の作業であれば、この警告は回避すべき技術的な不具合ではありません。非公式のリセットや更新の体験談を追いかけるのではなく、現在の有料プランや代替ツールを比較してください。

申請が当てはまらない場合、長く使える道は2つです。商用ライセンスを購入するか、商用利用の「地雷」がそもそもないツールに乗り換えるかです。

## 根本的な違い：無料プランの商用利用判定がない

AnyDeskは検出の仕組みを公開しておらず、直接接続とリレー接続の両方に対応しているため、警告が出たからといって画面のデータがAnyDeskのリレーを通った証拠にはなりません。**RustDesk Server OSS（無料のコミュニティサーバー）には商用利用の判定機能がまったくありません。** ライセンスのもとで、個人でも業務でも無料で使えます。RustDeskのクライアントとServer OSSは[AGPLライセンス](https://github.com/rustdesk/rustdesk)で、Server Proは商用のプロプライエタリなセルフホスト型サーバーソフトウェアであり、制限は購入したプランだけです。どちらでも、ランデブーとリレーのサービスを自社で運用できます。

## 2つのモデルの比較

|                                            | AnyDeskの無料プラン                                         | RustDesk                                                                                    |
| ------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 「商用利用」の検出                         | あり——無料利用の規約に基づきアクセスが制限されることがある | Server OSSには商用利用の判定機能なし。Proは購入したライセンスの上限を適用                   |
| セッションの経路                           | 可能なら直接、それ以外はAnyDeskのネットワークのリレー経由   | 可能なら直接、それ以外は自社のリレー経由                                                    |
| デバイスの許容数                           | AnyDeskの無料利用の規約で決まる                             | 商用プランは管理対象デバイス数でカウント                                                    |
| ソースコード                               | プロプライエタリなクライアント                              | 監査できるAGPLのクライアント                                                                |
| [同時接続数](https://rustdesk.com/pricing) | 無料プランでは制限あり                                      | 標準プランは無制限、[Customized V2](https://rustdesk.com/pricing#custom2)は制限あり         |
| 料金モデル                                 | 個人利用は無料、有料プランはシート単位                      | [ログインユーザー数＋管理対象デバイス数](https://rustdesk.com/pricing)                      |
| データの境界                               | AnyDeskが運用するサービス。メディアは直接またはリレー経由   | サーバー側のサービスは自社が管理するインフラで稼働。エンドポイント間の経路も考慮が必要      |

## セルフホスト型のRustDeskがサポートチームにもたらすもの

ライセンスは最初に取り決めます。Server Proのプランはログインユーザー数と管理対象デバイス数でカウントされ、標準プランには無制限の同時接続が含まれます。同時接続数をライセンスで定めるのは[Customized V2](https://rustdesk.com/pricing#custom2)だけです。[アップグレードはいつでも可能](/ja/blog/upgrade-rustdesk-license-mid-subscription-ja)で、有効期限はアップグレード日から丸1年に延長され、支払い済みの残存分が充当されます。顧客サポートの業務向けに、ProはセルフホストのWebコンソールと、ユーザー単位・デバイスグループ単位の[アクセス制御](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/permissions/)を提供し、Basicプランからはカスタムブランドのクライアントジェネレーターと[LDAP/OIDC SSO](https://rustdesk.com/docs/ja/self-host/rustdesk-server-pro/ldap/)も使えます。

## 次にすべきこと

フラグが誤検知だったなら、上記のホワイトリスト申請が解決策です。本当に商用利用であれば、まずServer OSSで試験導入してください。フラグのきっかけになったワークフロー（同じ技術者、エンドポイント、無人セッション、サポートの量）を再現し、年間契約を結ぶ前に、ライセンスの2つの指標（ログインユーザー数と管理対象デバイス数）を見積もります。どの代替ツールを検討するにしても、業務で導入する前にそのライセンスを読んでください。無料でダウンロードできるからといって、商用利用が自動的に認められるわけではありません。Proの評価条件については[sales@rustdesk.com](mailto:sales@rustdesk.com)までお問い合わせください。
